# Fuzzing

Coverage-guided fuzz targets for [libFuzzer](https://llvm.org/docs/LibFuzzer.html), one per
component, in their own package so the library never links the fuzzer runtime.

| Target | Checks against |
|---|---|
| `FuzzPriorityQueue` | A dictionary from index to priority: every query after every operation; a snapshot drains in order |
| `FuzzDisjointSet` | A naive label array: union results, `find`, `inSameSet`, `setSize`, `setCount`, canonical `labels()`, equality with a rebuilt value |
| `FuzzAdjacencyList` | Sets of vertices and pairs: neighborhoods, degrees, dense vertex and edge indices, edge positions, equality and hashing, snapshots |
| `FuzzUndirectedAdjacencyList` | The same for unordered pairs, with self-loops listed twice and each position at both ends |
| `FuzzShortestPaths` | Floyd–Warshall: Dijkstra on two representations, single target, A*, unweighted, Bellman–Ford, the negative-cycle witness, undirected Dijkstra |
| `FuzzSpanningTrees` | Brute-force minimum and maximum spanning forests: Kruskal, Prim, Borůvka and the default agree on weight, every result is a spanning forest |
| `FuzzUndirectedConnectivity` | Brute force by deleting each edge or vertex: components, bridges, articulation points, blocks, bi-edge-connected components, on three conformers and after mutations |
| `FuzzWalks` | The definitions: every walk, trail, path, circuit and cycle constructor, conversions, equality and hashing up to rotation |
| `FuzzCycles` | Brute-force enumeration by edge identity on multigraphs with loops: `simpleCycles` (set, canonical form, documented order), the bounded filter, `girth`, `isAcyclic`, `findCycle`, a cycle basis of m − n + c independent cycles; on `UndirectedAdjacencyList` after removals, a conformer without indices, `AdjacencyList` and the directed view |
| `FuzzTrees` | The definitions on edge lists with loops and repeats: `Tree`, `Forest` and `Arborescence` exist exactly when they should; at every root, parents, depths, children, preorder, postorder, descendants, ancestors and paths against a breadth-first search; Prüfer codes round-trip; parent arrays rebuild the tree |
| `FuzzTreeAlgorithms` | Trees of up to 200 vertices (across the 64-entry range-minimum blocks): lowest common ancestors and distances against climbing for every pair, heavy–light segments against the path, the Euler tour, center, centroid, diameter and the centroid decomposition against brute force |
| `FuzzDistances` | Floyd–Warshall on multigraphs with loops, both kinds, unweighted and weighted: eccentricities, radius, diameter, center, periphery (by bounding too), centroid, Wiener index, the diameter path |
| `FuzzCentrality` | Definitions on multigraphs with loops, directed and undirected, unweighted and weighted, with and without vertex indices: degree by counting, closeness and harmonic over Floyd–Warshall, betweenness from shortest-path counts (parallel copies distinct) in every scaling, one-vertex forms; eigenvector, Katz, PageRank and HITS as fixed points of their equations |
| `FuzzCommunityDetection` | Definitions on multigraphs with loops, directed and undirected, unweighted and weighted, without vertex indices: modularity by the matrix definition, coverage and performance by counting pairs, every result a partition in canonical order, greedy modularity a local optimum, label propagation a fixed point, Louvain at least the singletons' modularity, representations agreeing |
| `FuzzBipartiteGraphs` | Recognition against brute force over side assignments on multigraphs with loops (canonical sides, valid canonical odd cycles, `BipartiteGraph(graph)` agreeing), and mutation sequences on `BipartiteGraph` against a model: the invariant, counts, sides, degrees, parallel rows, orientation, order-free equality and hashing, the `init(_:left:)` round trip |
| `FuzzMatching` | Brute force on multigraphs with loops and parallel edges, without vertex indices: maximal and maximum matchings, Hopcroft–Karp's size, the minimum-weight full matching against enumeration; `linearSumAssignment` against every assignment of small matrices with forbidden pairs, minimizing and maximizing; `stableMatching` stable, proposer-optimal and matching the same agents as every stable matching |
| `FuzzCovering` | Brute force over vertex subsets on multigraphs with loops, without vertex indices: the lexicographically least maximum independent set, its complement as the minimum vertex cover, the least minimum dominating set, both approximations within their bounds of the weighted optima, maximality, König's cover as the minimum cover with the most left vertices, edge covers of n − ν edges, and the checks |
| `FuzzColoring` | Definitions and brute force on multigraphs of up to 9 vertices with loops, in shuffled vertex order, with and without vertex indices: every greedy strategy against first fit in its order computed from the definition with least-index ties, proper within Δ + 1 (smallest last within degeneracy + 1), first fit in a given order; χ as the least k with a proper colouring, the least optimal colouring per component by restricted-growth search; Misra–Gries proper with Δ or Δ + 1 colours; König exactly when bipartite, with exactly Δ colours counting parallel edges; `isColoring` and `isEdgeColoring` on arbitrary colourings |
| `FuzzMultigraphs` | Random insertions and removals (newest copy, a position, every copy of a pair, a vertex) on the pseudographs against a model of positions with the swap-remove rule: counts, every edge at its position, `edges(between:)` oldest first, degrees, parallel rows, order-free equality and hashing |
| `FuzzCliques` | Brute force over vertex subsets on multigraphs with loops, with and without vertex indices: maximal cliques, clique number, the least maximum clique, core numbers by peeling, the degeneracy ordering's property, triangles, clustering, transitivity |
| `FuzzFlows` | Invariants without an oracle on multigraphs with loops, parallel and antiparallel edges, directed and undirected, with and without indices: the three maximum flows within capacity, conserved, of equal value, with the canonical cut (the residual sink side), its edges separating the terminals at the max-flow value; dyadic `Double` capacities scaled; the directed global cut as the least pair, Stoer–Wagner at most every pair and equal to the least λ(v₀, v), Gomory–Hu against every pair's max flow; minimum-cost flows feasible with the potentials' optimality certificate and nil exactly when a super-source flow falls short; λ and κ (local and global) against flows and deletion; `Int8` and `UInt8` near their maximum agreeing with `Int` wherever the documented preconditions hold |
| `FuzzTours` | Invariants without an oracle on multigraphs with loops, parallel and antiparallel edges, shuffled labels, on `Pseudograph`, `DirectedPseudograph`, the undirected view, `CompressedSparseRow` and conformers without indices: Eulerian facts exactly when the degree and connectivity rules say, every circuit and trail a genuine walk using each edge once from the documented start (and `(from:)` for exactly the documented starts); Hamiltonian paths and cycles genuine, existing exactly when a bitmask dynamic program says (n ≤ 10), from the first vertex that has one; tours on complete multigraphs through each pair's lightest copy, nearest neighbour by its definition, 2-opt no heavier than its start and 2-optimal, Held–Karp equal to brute force with its lexicographically least optimum (n ≤ 8) and no heavier than any heuristic, Christofides within 3/2 on Manhattan points, `Double` quarters scaled; Held–Karp on non-complete graphs nil exactly without a Hamiltonian cycle, and on directed multigraphs equal to brute force over each ordered pair's lightest arc; the same tours without indices |
| `FuzzLabeledGraphs` | A model of labels in index order and index pairs: builds of both bases through every initializer, matrix mutation sequences, every row by label and by index, `safe:` spellings, breadth-first layers, components and Dijkstra against the base mapped through the labels, order-free equality (by multiplicity over a pseudograph base), hostile `init(from:)` payloads throwing at the documented key |
| `FuzzDirectedAcyclicGraph` | A model of the vertex set and edge multiset, on AdjacencyList, DirectedPseudograph and StableDirectedGraph bases driven by one sequence of insertions (sources arriving last among them; a new source to an old target must be placed first and any other new endpoint last), removals and resets, with churn across a 1024-key page and label renumbering: the order a permutation with every edge forward, positions and lookups agreeing, rejection exactly when the model closes a cycle (nothing changes, the `bidirectionalShortestPath` witness a genuine shortest path), Kahn order from bulk construction, locality of reordering; closure, reduction (first copies), longest path (first ties) and `hasPath` against brute force; hostile `init(from:)` payloads throwing at the documented key, a base at position 2³⁶ included |
| `FuzzFunctionalGraphs` | Brute-force orbit iteration on random mappings, permutations and long tails: the cycle decomposition (cycles from their least vertex, tails, roots, components, preimages), `successor(of:steps:)` on the graph and the decomposition against stepping and, up to `Int.max`, the orbit's tail and period; Floyd and Brent from every vertex against the decomposition, with Floyd's exact call count; the `DirectedPseudograph` round trip. `ImplicitDirectedGraph` against a `DirectedPseudograph` of the same rows: edges by iteration and by index stepping, positions, rows, degrees, membership with the closure's call counts, components, layers, Dijkstra. The closure Dijkstra and A* (exact, scaled-down inconsistent heuristics, `Double` weights) against a quadratic Dijkstra: distance, nil, a genuine path of that cost, one expansion per state when the heuristic is consistent; under a cutoff, the same answer when the nearest goal is that close and nil otherwise |
| `FuzzGenerators` | Every NamedGraphs and RandomGraphs family on the 3 undirected and 6 directed conformers, the random DAG on 3 bases, `Tree.path`/`star`/`random` and `BipartiteGraph.completeBipartite`, with small fuzzed sizes and parameters (out-of-range ones are screened by the documented preconditions and never called): the representation contract (vertices 0..<n, edges strictly sorted, degrees and rows from the edges); the deterministic families equal to written-out models; G(n, p) empty or complete with no draws at p = 0, 1 − p = 1 and p = 1, G(n, m) with m edges, Barabási–Albert's counts and new-to-old structure (the directed form its reverse on the same draws), Watts–Strogatz's nk/2 edges and its ring at p = 0, the geometric graph equal to the distance test on the returned positions, the block model's empty and full block pairs; the random DAG equal to the undirected G(n, p) or G(n, m) on the same seed with order 0..<n; random trees with n − 1 edges and no cycle; every conformer the same edges and generator state, and the same seed the same graph |
| `FuzzHypergraphs` | A model of vertices in index order and hyperedges as ascending index rows (both sides when directed): bulk, hyperedges-only and one-call-at-a-time builds, mutation sequences with `safe:` spellings and resets, every row by vertex and by index, membership and near misses; neighbors, rank, histograms, dual, clique expansions, s-line graph, components and s-components against direct computations; B- and F-connection against the fixpoint of Gallo et al.'s definition, strong components by reachability; both incidence-graph views against adjacency-list copies; `IncidenceMatrix` and `OrientedIncidenceMatrix` against the lists and under cell edits past a word of rows or columns; order-free equality and hashing; hostile `init(from:)` payloads (repeats, indices out of range, rows not ascending, side lengths, negative or oversized or overflowing shapes, the `userInfo` limit) throwing, never trapping |
| `FuzzIsomorphism` | Brute force over every injection on multigraphs with loops and parallel edges (at most 7 target vertices), directed and undirected, with optional vertex and edge colours: isomorphism, induced subgraph isomorphism and monomorphism as yes/no, first mapping and the whole sequence (its count, no repeats, each mapping valid by the definition); relabelled copies (vertices listed and edges inserted in other orders) always isomorphic, the relabelling among the coloured isomorphisms, with equal Weisfeiler–Leman graph and per-vertex hashes in every overload; the automorphism group's order, orbits and generators against brute force in each colour overload, canonical forms equal exactly when isomorphic |
| `FuzzPlanarity` | Random multigraphs (loops, parallel edges, vertices listed in a random order) up to 12 vertices and 40 edges: the left-right test (`isPlanar`, `planarEmbedding()`) and Boyer–Myrvold (`findKuratowskiSubgraph()`) agree; each clockwise order a permutation of the incident edges from the first, with the neighbours across it; faces traced from the rotation equal to `faces`, `face(from:alongEdgeAt:)` and `rightFace(from:alongEdgeAt:)` from every half-edge; Euler's count per component; every witness a subdivision of its kind with ascending edges, no loop, one copy of a pair, its paths in order and internally disjoint, and minimal; `isOuterplanar` equal to Boyer–Myrvold on the graph plus an apex; the same results on a second call |
| `FuzzSpectral` | SpectralGraphTheory on random weighted pseudographs given as a plain edge list (loops, parallel edges, weight-0 edges; weights unit, small integers or log-uniform over up to 2^±20): on 64 to 95 vertices, λ₂ of L and of N by Lanczos (shifted or shift-invert) against the dense spectrum, the Fiedler residual, unit length and orthogonality to the null vector, ρ(A) against the dense spectrum with negative weights; on up to 9 vertices, the matrix-tree count against a Bareiss determinant in Int128 (exact below 2⁵³), τ under power-of-two scaling, resistance as a metric, Foster's theorem, the pairwise sum against `effectiveGraphResistance`, and the Kemeny constant against (1/2vol) Σ dᵢdⱼR(i, j) |
| `FuzzSemirings` | The semiring laws on random values with the sentinels, then random multigraphs with loops and parallel edges: tropical Dijkstra (cutoff, single target), Bellman–Ford, Floyd–Warshall and DAG paths against the `W` overloads over Int and Double, with the tropical zero as an edge that carries no path; widest paths against every simple path; DAG path counts against enumeration, on the graph and on `DirectedAcyclicGraph`, and `nil` exactly when a cycle is reachable; Boolean Floyd–Warshall, Dijkstra and Bellman–Ford against breadth-first search; the undirected overloads on a `Pseudograph` and on an `UndirectedAdjacencyList` of strings; tropical −∞ (`Int.min`) edges on cycles against the `W` engine with −∞ stood in by -1000, `nil` together; UInt, Int8 and Float against Int, Double and the enumeration; NaN weights on edges the sources never reach leave Dijkstra and Bellman–Ford unchanged; every tree and matrix path a walk whose product is its distance |

Each target reads its input as a sequence of small choices (`FuzzInput`): an operation and its
arguments, or a graph's size, edges and weights. Every byte string decodes, and a mutation of one
byte changes one choice, so libFuzzer explores operation sequences rather than parse errors.

## Running

| Command | Does |
|---|---|
| `just fuzz` | Every target for 60 s, all at once, splitting the cores between them |
| `just fuzz FuzzShortestPaths -t 600 -j 16` | One target for 10 minutes on 16 workers |
| `just fuzz-regress` | Replays every corpus once (seconds); run after changing a fuzzed module |
| `just fuzz-repro <target> <crash file>` | Replays a crash and writes a minimized copy beside it |

A run is bounded by wall time. New inputs that add coverage are merged into `Fuzz/Corpus/<target>/`
(local, not committed), so the next run resumes from there. Crashes are written to
`Fuzz/Crashes/<target>/`; each one becomes a test in the module's suite, and then the file is
deleted.

## Toolchain

Xcode's toolchain does not include the libFuzzer runtime (`libclang_rt.fuzzer_osx.a`); the
swift.org toolchains do. The scripts build with `swiftly run swift build +6.3.3` (override with
`GRAFLUENT_FUZZ_SWIFT`), so install it once with `swiftly install 6.3.3`. The build prints
`unknown argument: '-target-arch-variant'` while reading the newer SDK's interfaces, then falls
back and succeeds; the scripts hide it.

Targets are built in release mode with AddressSanitizer: preconditions stay on, and the unsafe
buffer code in the representations and the heap is checked for out-of-bounds access.

SwiftPM links each executable against its own `main`, which conflicts with libFuzzer's, so each
target has an `@main` that calls `runFuzzer`, which starts libFuzzer through
`LLVMFuzzerRunDriver`.

## Adding a target

Add `Sources/Fuzz<Name>/Fuzz<Name>.swift` with an `@main` enum calling `runFuzzer`, and a line in
`Package.swift`. Check against a model simple enough to be obviously right, check after every
operation, keep values small (vertices 0..<10, priorities 0..<8) so collisions and ties are common,
and include a snapshot copy to catch copy-on-write bugs.
