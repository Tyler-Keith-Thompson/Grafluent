Changing a stored graph

How can a graph keep changing without losing the speed of packed arrays?

What it’s forGraphs that change all the time

Most real graphs are never finished. People follow and unfollow. Servers come and go. A route map gets a new road every week. The algorithms that run on these graphs want each vertex’s neighbours packed side by side in memory, because a computer reads memory fastest in order. Compressed sparse row stores the rows that way, but it can’t take a new edge without a rebuild. An adjacency list takes new edges all day, but a row that outgrows its space moves to the end of the storage, so after many changes the rows sit in no particular order and reading them all slows down.

Packed rows keep both. Every row stays packed, in order, with a few spare cells after it. Adding an edge usually fills a spare cell. When a row runs out, a window of rows around it is laid out again to share the spare cells around. Reading the whole graph reads one array from start to end, as compressed sparse row does. Reach for PackedCompressedSparseRow when a graph keeps changing and you keep running whole-graph algorithms over it between the changes.

Compared withThree ways to store a changing graph

The adjacency list is the default. Packed rows cost about twice as much per added edge and read the whole graph a little faster, so they only win when reads far outnumber changes. A rule of thumb: reach for packed rows when each change is followed by about a thousand edge reads or more, such as a few whole-graph algorithms run between batches of updates. If the graph stops changing before the algorithms run, build a compressed sparse row instead, which is faster still and costs nothing to keep.

Example: six people and who follows whom, with the storage drawn underneath. It starts built in one go, so the rows are packed tight. Add one follow and watch the storage spread out with spare cells. Keep adding and most follows drop into a spare cell. Fill it up and the whole storage doubles.

The ideaA bookshelf with gaps

Think of a bookshelf where each person’s books stand together, with a little empty space after each run. A new book usually slides into that space. When one run has no space left, you look at the shortest stretch of shelf around it. If that stretch is not too full, you spread its books out again so every run gets some space. If it is too full, you take a longer stretch, and longer again. Only when the whole shelf is more than seven tenths full do you buy a shelf twice as long.

Packed rows do exactly that with cells. A short stretch may fill up to 92 percent before it is spread out again, but the whole storage is kept no more than 70 percent full. Longer stretches get a limit in between, so a spread at any size leaves its rows room to grow before they ask again. An array kept this way is called a packed memory array, and this graph built on one is the packed compressed sparse row of Wheatman and Xu. Most inserts move a handful of cells, a large spread is rare, and reading every row reads the storage once, forward.

Grafluent numbers every edge by a position, and that position is how you keep a weight or a label for it in a separate array. Positions survive all of this. A spread moves cells, never the position an edge goes by, so anything attached to an edge stays where it is.

Where it breaksAdding at the end, over and over

The spare cells are spread out evenly, but a stream of inserts that all land in the same place uses them up there first. Adding vertices one after another, each with its edges, always hits the newest row at the end of the storage. The end fills, spreads, fills again, and each spread is larger than the last. It still works, but each insert costs more than on a graph whose inserts land anywhere. If that is your pattern, build with an adjacency list and convert once, or build in one go.

Removing an edge is cheap: the row’s last entry moves into the hole, and the cell is spare again. When fewer than a quarter of the cells are in use, the storage halves, so memory follows the graph down as well as up.
