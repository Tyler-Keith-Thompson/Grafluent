Graph basics

What exactly is a graph, and which kinds will you meet on these pages?

A graph has two parts. Vertices are the things you care about, such as cities, people, web pages or tasks in a build. Edges join pairs of them. An edge might be a road, a friendship, a link or a dependency. Many libraries and papers call vertices nodes. The two words mean the same thing.

DirectionUndirected and directed


In an undirected graph an edge works both ways, like a friendship or a two-way street. In a directed graph each edge has a start and an end, and it is drawn as an arrow. Think of a one-way street, a link from one page to another, or “compile before test”. Grafluent keeps the two as separate kinds of graph. So an algorithm that only makes sense for one can’t be handed the other by mistake.



WeightsNumbers on the edges


Often an edge carries a number, such as the minutes to walk a street, the cost of a cable, or how much a pipe can carry. That number is the edge’s weight, and a graph with weights is a weighted graph. Grafluent never stores weights inside the graph. You keep them wherever suits you, and you pass the algorithm a way to look each one up. So the same graph can be measured in minutes on one page and in kilometres on the next.



Walks, paths and cyclesRoutes, and routes that come back


A walk is any route you can trace along edges, one after another. It may pass the same vertex or edge more than once. A path is a walk that never visits a vertex twice. A cycle is a walk that ends where it started and repeats no other vertex on the way.



Cycles matter a lot. A road network is full of them. Tasks with dependencies must have none, or no order could ever finish them. Grafluent has a type for each kind of route, Walk, Path and Cycle. An algorithm that returns a route returns the type that says what it guarantees.


Two more you’ll seeSelf-loops and parallel edges


A self-loop is an edge from a vertex to itself, like a road that leaves a town and comes back. Parallel edges are two or more edges between the same pair, like a highway and a back road between the same two towns. A graph that allows them is called a multigraph. Grafluent tells parallel edges apart by their position in the graph, so each one can have its own weight.

Words you’ll meetA few more terms, defined once

  
Later pages lean on these. Each is explained again where it matters, and this list is here to come back to.

  

    
Neighbours

    
Two vertices joined by an edge are neighbours. In a directed graph, the vertices a vertex’s arrows lead to are its successors, and the vertices whose arrows lead to it are its predecessors.

    
Degree

    
How many edges touch a vertex. In a directed graph, the in-degree counts the arrows coming in and the out-degree the arrows going out. A hub is a vertex with far more edges than most.

    
Sparse and dense

    
A graph is sparse when it has far fewer edges than it could, and dense when most pairs are joined. Most real graphs are sparse. A complete graph joins every pair.

    
Simple graph

    
A graph with no self-loops and no parallel edges.

    
Connected

    
An undirected graph is connected when there is a route between any two of its vertices. The largest pieces that are each connected are its components.

    
Tree

    
A connected graph with no cycles. A tree on n vertices has exactly n − 1 edges. Choose one vertex as the root, and every other vertex has one parent, its next step toward the root. A vertex’s children are the vertices it is the parent of, a leaf has no children, its depth is its number of steps to the root, and its ancestors are its parent, its parent’s parent, and so on up. A subtree is a vertex with everything below it. A forest is several trees side by side. A spanning tree of a graph is a tree made from the graph’s own edges that reaches every vertex.

    
Directed acyclic graph

    
A directed graph with no cycles, such as tasks and the tasks each one waits for. The short name is DAG.

    
Bipartite

    
A graph whose vertices split into two sides, with every edge joining one side to the other, like workers and jobs.

    
Subgraph

    
Some of a graph’s vertices and some of the edges between them.

    
Hash table and binary search

    
A hash table is the structure behind a dictionary. It finds a key in about one step however many keys it holds. A binary search finds a value in a sorted row by halving the row again and again.

  







SpeedHow these pages talk about speed

  
On these pages n is the number of vertices and m the number of edges. A cost written O(n + m) says how the work grows with the graph, leaving out constant factors. This one grows in step with vertices plus edges, so a graph twice the size takes about twice as long. O(m log n) grows a little faster than the edges, because log n stays small, about 20 for a million vertices. O(n²) grows with the square, so doubling the graph quadruples the work. Constant time, O(1), means the same few steps however big the graph. Exponential, such as O(2n), means the work can double with every vertex added, which suits only small graphs.

  
Some problems are NP-hard. No known method is fast on every input, and the exact methods are exponential. For those, a page offers a heuristic, a rule of thumb that gives a good answer quickly without promising the best one. A greedy method is the simplest heuristic. It always takes the move that looks best right now and never undoes it.
