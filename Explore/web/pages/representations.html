Storing a graph

How does a computer keep a graph in memory, and why does it matter which way?

One example runs through this page: four friends and who follows whom. Ana follows Ben and Cy, Ben follows Cy, Cy follows Ana, and Dee follows Cy. That’s a directed graph with four vertices and five edges. Add or remove a follow and watch all three forms change together.

In SwiftThe friends above, in Grafluent







  
Adjacency listA row of neighbours per vertex

  
For each vertex, keep a list of the vertices its edges point to. To ask “who does Ana follow?”, look up Ana’s list. Its size grows with the number of edges actually present, so it suits big graphs where each vertex has only a few neighbours, which is most real ones. Adding and removing edges is cheap. Grafluent’s AdjacencyList also keeps each vertex’s incoming edges, so “who follows Cy?” is just as quick.


  
Adjacency matrixA square for every pair

  
Make a grid with one row and one column per vertex. Put a 1 in row r, column c when there is an edge from r to c, and a 0 otherwise. Rows say who follows; columns say who is followed. To read it, pick a row and go across: Ana’s row has 1s under Ben and Cy, because Ana follows them. To find who follows Cy, read down Cy’s column instead. For an undirected graph the grid is symmetric, a mirror image across its diagonal, because every edge counts both ways: switch to friends above to see it.

  
The matrix answers “is there an edge from r to c?” in one look-up, however big the graph. The price is space: it needs a square for every pair of vertices, edge or no edge. Four friends need 16 squares; a million need a trillion, almost all of them 0. Grafluent’s AdjacencyMatrix stores each square as one bit.


  
Compressed sparse rowTwo plain arrays

  
Take the adjacency list and pack every row end to end into one array of targets. A second, shorter array of offsets records where each vertex’s run starts. Ana’s run starts at 0 and Ben’s at 2, so Ana’s targets are positions 0 and 1. The last offset marks the end, so a vertex’s run always ends where the next one starts.

  
Two plain arrays are as compact as a graph gets, and walking them is about the fastest thing a processor can do. The trade-off is that you can’t add an edge without rebuilding the whole thing.


  
When to use whichOne answer, three speeds

  
    
    
  • Adjacency list (AdjacencyList): the default. Use it for any graph that changes.
    • 
    
  • Adjacency matrix (AdjacencyMatrix): small graphs, or ones where most pairs are connected, and anything that asks “are these two connected?” over and over.
    • 
    
  • Compressed sparse row (CompressedSparseRow): a large graph you build once and then analyse many times.
    • 
  

  
The matrix and CSR number their vertices 0, 1, 2…; a LabeledGraph puts names on those numbers, which is how this page keeps “Ana” and “Ben”. Every algorithm on this site runs on all three forms. The answer is the same; only the speed and memory differ.
