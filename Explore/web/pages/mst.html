Minimum spanning trees

Say itKRUSS-kul/ˈkrʌskəl/

What’s the cheapest set of cables that connects every house?

Example: six houses and the cost of laying cable between each pair that can be connected.

In SwiftThe six houses, in Grafluent







  
The ideaTwo ways to the same cheapest network

  
Kruskal sorts every possible cable from cheapest to dearest and lays each one unless it would only join two houses that are already connected. Prim grows a single network outward from one house, always adding the cheapest cable that reaches a house not yet connected. Different routes, same total cost.

  
Either way the result is a spanning tree: every house is connected, and there are no loops, so six houses need exactly five cables. A loop would mean one cable could be removed without disconnecting anyone, which is money wasted.

  
Kruskal keeps track of who is already connected with a union–find structure, which answers “same group?” almost instantly. Prim keeps a queue of the houses waiting to join, each with the cheapest price on offer so far, just as Dijkstra keeps its frontier.


  
Where it breaksCheapest isn’t shortest

  
The cheapest network isn’t the one with the shortest routes. The trip between two houses can be long and winding. If travel time matters, that’s a shortest-path problem.

  
Here a direct Dev–Eli cable would cost 5, and it isn’t in the network: a signal from Dev to Eli goes through Ada and Ben, three cables instead of one.
