Prefix tree

You type “ca”. Which words could you mean, and how does the search box find them so fast?

Example: nine short words. Each vertex of the tree is a prefix of some word, and each edge adds one letter. The words that start with what you typed all hang below one vertex.

The ideaShare the beginnings

  
A prefix tree, or trie, stores a set of words so that words with the same beginning share it. The root is the empty prefix. Adding a word walks down from the root letter by letter, following an edge where one already exists and making a new vertex where none does; the vertex the word ends at is marked. “cart” after “car” and “card” costs one new vertex, because “car” is already there.

  
Looking up is the same walk. Follow the letters typed; if an edge is missing, no word starts that way. Otherwise every marked vertex below the one you reached is a word with that beginning. The walk costs the length of what you typed, however many words the list holds, and listing the suggestions costs the size of the part below.

  
prefixTree(of:) builds one from any sequences of hashable symbols, not just words: lists of moves, paths in a file system, IP address bits. The tree is an Arborescence on vertex numbers, with the symbol of each edge and the vertex where each sequence ends.


  
Where it breaksMany vertices, and only exact beginnings

  
One vertex per distinct prefix adds up: a large dictionary has millions, mostly in long single-file chains near the leaves. Compressed tries (radix trees) merge each chain into one edge labelled with a whole string, and a sorted array with binary search often does just as well for a fixed list.

  
A prefix tree also only finds words that start exactly with what was typed. A real search box ranks suggestions by how often they are chosen, and forgives typos, which needs edit-distance search or a different index altogether.
