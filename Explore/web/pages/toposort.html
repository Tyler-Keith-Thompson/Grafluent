Topological sort

Say ittop-uh-LOJ-ih-kul/ˌtɒpəˈlɒdʒɪkəl/

In what order can you do tasks that depend on each other?

Example: getting dressed. Socks before shoes, shirt before tie, trousers before belt. Add a new rule and watch the order update.

In SwiftThe wardrobe above, in Grafluent







  
The ideaDo whatever has nothing left to wait for

  
Draw an arrow from each task to anything that has to wait for it. A valid order lists every task before everything its arrows point to. One way to find it, Kahn’s: repeatedly take any task with no arrows coming in, write it down, and remove it, which may free up others. Each round of that frees a wave of tasks that could all happen at the same time.

  
Grafluent’s topologicalSort() uses the other classic way: a depth-first search, listing each task once everything after it is finished, then reading the list backwards.


  
Where it breaksRules that go round in a circle

  
Add “shoes before socks” and there is no valid order at all: the rules go round in a circle. topologicalSort() returns nil, and findCycle() hands back the circle, so you can see which rule to drop.
