Dominators

Say LengauerLENG-ow-er/ˈlɛŋaʊ̯ɐ/

Which parts of a program are sure to have run by the time it reaches a given line?

What it’s forWhat every path must pass through

A block is a run of code with no jumps in it. A block dominates another when every path from the entry, where the function starts, to the second passes through the first. Dominators tell you what is sure to have happened before a point is reached. Post-dominators tell you what is sure to happen after it.

Compilers rely on them. They use dominators to find loops, to decide where a variable set on two branches needs merging, and to move code out of a loop safely. The same idea finds the single points every route must pass in any network with one entry.

Compared withOther ways to find dominators

All three give the same tree. Lengauer–Tarjan has the best bound. The second lab on this page runs the slowest method, because it follows the definition.

Example: a function that adds up the numbers in a file, line by line. It warns about lines that aren’t numbers, and gives up after too many. Each block is a run of code with no jumps in it. The arrows are the jumps.

func total(of lines: [String]) throws -> Int {
    var sum = 0, bad = 0, count = 0            // entry
    for line in lines {                        // loop
        if let n = Int(line) {                 // check
            sum += n                           // add
        } else {
            bad += 1                           // warn
            if bad > 3 { throw TooManyBad() }  // give up
        }
        count += 1                             // next
    }
    return sum                                 // done
}                                              // exit

The ideaThe blocks you can’t get around

  
Each block has a chain of dominators running back to the entry. The nearest one is its immediate dominator. Every block except the entry has exactly one. So drawing each block under its immediate dominator gives a tree, the dominator tree. A block’s ancestors in that tree, its parent, its parent’s parent and so on up to the entry, are exactly the blocks that dominate it. That is why dominates(_:_:) answers in constant time once the tree is built.

  
The second lab follows the definition. Take a block out and search from the entry. Whatever is cut off is what that block dominates. That costs one search per block.

  
Lengauer and Tarjan get every immediate dominator from a single depth-first search. First each block gets a semidominator, a first guess at the immediate dominator from the search order. That is the earliest block, in the search’s order, with a path to it that detours only through later blocks. One more pass over the tree the depth-first search walked (as on Bridges) turns semidominators into immediate dominators. Grafluent’s dominatorTree(root:) runs this algorithm.

  
Turn every arrow around and start from the exit instead. Then you get post-dominators, the blocks sure to run after a given one. postDominatorTree(exit:) finds them. A loop’s head dominates its body, which is how compilers find loops. The dominance frontier is where one block’s dominance stops. A variable assigned in two branches needs a merge there, at the first block where both assignments can arrive. dominanceFrontiers(root:) lists these frontiers.


  
Where it breaksCode nothing reaches, and code that never ends

  
A block the entry can’t reach has no dominators at all. “Every path passes through” means nothing when there is no path. So dominators(of:) returns nil for such a block, and not an empty list. That way dead code can’t be mistaken for code with no requirements.

  
Post-dominators have the same gap from the other end. A block that loops forever never reaches the exit. In a function with two exits, some paths never reach the exit you named. Give every exit a jump to one shared exit block first.

  
Dominance is about the jumps as drawn. It ignores the values that choose between them. Here give up only ever follows several warnings. But the graph sees one arrow from warn, and no count. What dominators promise holds on every path through the graph, so a compiler can rely on them. Facts that depend on the data are beyond them.
