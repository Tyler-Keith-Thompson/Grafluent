Tree edit distance

The org chart changed over the year. How many moves, hires and departures does it take to get from the old one to the new?

What it’s forHow far apart two trees are

Edit distance on strings counts the fewest insertions, deletions and substitutions between two texts. Tree edit distance does the same for ordered trees: delete a vertex and its children move up to its parent, insert one and it takes a run of siblings under it, or substitute one vertex for another. The distance is the cheapest script.

Reach for it to compare org charts, XML or JSON documents, syntax trees of two programs, RNA secondary structures, or any two things that are trees with an order among siblings.

Compared withOther ways to compare structures

Tree edit distance sits between a yes-or-no isomorphism test and the exponential graph edit distance: it keeps the nesting and stays polynomial by using the order of siblings.

Example: last year’s org chart and this year’s, with one move, one departure and a new team.

Step throughEdit one chart into the other

The ideaSubtrees in postorder, forests in between

Zhang and Shasha’s algorithm numbers each tree’s vertices in postorder, so a subtree is a run of consecutive numbers, and so is a forest of the subtrees to its left. It fills a table of the distance between every pair of such runs, each entry from three smaller entries: delete the last vertex of one side, insert the last of the other, or match the two last vertices and recurse on what is left. Only the subtrees rooted at the keyroots, the leftmost paths’ tops, start a fresh table, which keeps the work to the bound in the compare table. treeEditDistance(to:) returns the distance at unit costs, where a substitution is free, so it measures how far apart the shapes are; the longer form takes a cost for each kind of edit, so a change of name can cost what it should.

The lab charges 1 for a deletion or an insertion and 2 for a change of name, turns last year’s chart into this year’s with the cheapest edits, and asks the distance to the goal after each, so the number counts down to zero. Moving Cy costs two, a deletion and an insertion, because an edit never moves a vertex to a new parent in one step. With names free, the shapes alone are only three edits apart.

Where it breaksOrder and size

The trees are ordered: swapping two siblings costs edits, which is right for documents and code and wrong for family trees or chemical structures, where sibling order means nothing. Unordered tree edit distance is NP-hard, so a different tool, or a canonical sibling order, is needed there. The table is n × n′ entries, so two trees of ten thousand vertices need a hundred million of them.
