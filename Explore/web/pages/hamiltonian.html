Hamiltonian cycles

Can you visit every place exactly once and end where you began?

What it’s forEvery place, exactly once

A Hamiltonian cycle is a round trip that visits every place exactly once. A Hamiltonian path does the same without coming back. Finding one answers questions like whether a tour can cover every stop without repeats, or whether a puzzle can be solved. No fast method is known, so the search tries routes and backs up.

Reach for it on small graphs, or to check a puzzle. When the roads have lengths and you want the shortest such tour, that is the travelling salesman problem. When you need every road once, not every place, use an Euler tour, which is easy.

Example: the icosian game, which William Rowan Hamilton sold as a puzzle in 1857. Twenty places sit at the corners of a dodecahedron, flattened onto the page. Each is joined to three others. The goal is a round trip through all twenty.

The ideaEvery vertex once, not every edge

  
An Euler tour uses every road once. There is a quick test for whether one exists, because every place needs an even number of roads. A Hamiltonian cycle uses every place once, and no such test is known. The general question is NP-hard. As far as anyone knows, answering it for every graph takes time that grows exponentially with the graph.

  
So the search tries. Grafluent’s hamiltonianCycle() grows a route one place at a time. It always goes to the first neighbour not yet visited, and it backs up when it gets stuck. The second lab does the same.

  
The search also stops early in a branch that can’t work. That happens when some place left over can no longer be reached, or has too few unvisited neighbours to pass through. This pruning doesn’t change which cycle comes out first. It only changes how long the search takes.

  
hamiltonianPath(from:to:) asks the same of a route with fixed ends. The first lab uses it to check whether your route can still be finished. What is left must have a path from your current place, through everything unvisited, back to the start.


  
Where it breaksSmall graphs, or special ones

  
The dodecahedron is solved in a moment. It is small, and every place has only three roads. Each added place multiplies the routes to try, and a few hundred places can be out of reach.

  
For larger graphs there are useful tests that can only say yes. Dirac’s theorem says that a graph of n ≥ 3 places always has a Hamiltonian cycle when each place is joined to at least half of the others. A graph that fails such a test may still have one.

  
Proving that a graph has no Hamiltonian cycle is harder still, because the search has to rule out every route. The Petersen graph, with ten places and three roads each, is the classic example. hamiltonianCycle() answers nil for it only after it has tried everything.
