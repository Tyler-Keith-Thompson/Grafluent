Bridges and articulation points

Which single road closure splits the town?

What it’s forThe weak spots in a network

A bridge is a road whose closure cuts a network in two. An articulation point, or cut vertex, is a place whose closure does the same. Finding them shows where one failure would cut someone off.

Reach for them to check a road map, a power grid or a computer network for single points of failure. One depth-first search finds every one of them.

Example: a village of nine places and ten two-way roads. First close a road or a place yourself. Then step through the search that finds them all.

The ideaCan you get back without the road you came by?

  
You could try every closure in turn. That means one connectivity check per road, which is slow on a big network. A single depth-first search answers for every road at once.

  
The search numbers each place by when it first arrives there. That number is the place’s time. The roads the search walks to new places form a tree. Every other road leads back to a place already on the current path. These are back roads.

  
Each place also keeps a low-link. It is the earliest time that the place, or anything the search reached from it, can get back to with one back road. When the search leaves a place, its low-link is final. Then one comparison with its parent decides everything.

  
    
    
  • Say the low-link is later than the parent’s time. Then nothing below gets back to the parent except by the tree road between them. That road is a bridge.
    • 
    
  • Say the low-link is no earlier than the parent’s time. Then the branch below can’t get above the parent, so the parent is an articulation point. The start is the exception. It is one only when the search had to set out from it more than once.
    • 
  

  
Each road is looked at once from each end. So the whole search takes time in proportion to the places plus the roads. Grafluent’s bridges() and articulationPoints() run this search. The step-through lab rebuilds the times and low-links from the events of lazy.edgeDepthFirstSearch.


  
Where it breaksLoops have no bridges, and that’s the point

  
Mill, Church, Square and School form a loop. Station, Market and Harbour form a triangle. Inside either one, no single closure cuts anyone off, because there is always another way round. Such a part is two-edge-connected, and biEdgeConnectedComponents() lists them. So the cure for a fragile network is a loop. Add one new road from Farm to Church, and Mill–Farm stops being a bridge.

  
Places are a different question from roads. Two triangles that share one corner have no bridge at all. Yet taking away the shared corner splits them. Each triangle is a block, or biconnected component, and the corner is in both.

  
  
A network that must survive any one failure needs no articulation point, which isBiconnected checks. To survive any two failures, you need to count the separate routes that join each pair. That is a question of flow.
