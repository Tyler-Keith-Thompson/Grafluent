Travelling salesman

What is the shortest round trip that visits every town once and comes home?

What it’s forThe shortest round trip

The travelling salesman problem asks for the shortest round trip that visits every town once and comes home. Delivery rounds, drilling holes in circuit boards and ordering a telescope’s targets all ask it.

Nobody knows a fast way to find the exact answer for every map. So in practice you build a good tour quickly, then improve it. The exact answer is only within reach for a few dozen towns.

The fast methods give good tours on thousands of towns. Only Held–Karp is exact. In the table, n is the number of towns.

Example: eleven towns, with every pair joined by a straight road. There are 1,814,400 different round trips through them.

import AdjacencyListModule
import GraphProtocols
import RandomGraphs
import Tours
import Walks

// Each town and where it is, in km east and south of the map's corner.
let towns: [(name: String, x: Double, y: Double)] = [
    ("Ashby", 10, 22), ("Brook", 32, 6), ("Carlow", 56, 16), ("Dunmore", 82, 5),
    ("Elmsford", 112, 20), ("Fenwick", 94, 46), ("Glenby", 114, 74), ("Harlow", 74, 64),
    ("Ivybridge", 46, 76), ("Kelso", 18, 60), ("Lynton", 52, 42),
]

// Every pair of towns, joined by a straight road of its length in whole km.
let roadList = towns.indices.flatMap { i in towns[(i + 1)...].map { UndirectedEdge(towns[i].name, $0.name) } }
let tourMap = UndirectedAdjacencyList<String> {
    for road in roadList { road }
}
let km = tourMap.edges.map { road in
    let a = towns.first { $0.name == road.u }!, b = towns.first { $0.name == road.v }!
    return Int(((a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y)).squareRoot().rounded())
}

let start = "Ashby"

let greedy = tourMap.nearestNeighborTour(from: start) { km[$0] }!

let improved = tourMap.twoOptTour(improving: greedy) { km[$0] }!

var generator = Xoshiro256StarStar(seed: 1)
let annealed = tourMap.simulatedAnnealingTour(
    improving: greedy, move: .relocate, temperature: 50, maximumIterations: 200, innerIterations: 500, weight: { km[$0] }, using: &generator)!
let christofides = tourMap.christofidesTour { km[$0] }!
let shortest = tourMap.shortestTour { km[$0] }!

let tour = improved

let length = tour.weight { km[$0] }  // 364

The ideaA good tour fast, then a better one

Nearest neighbour is what most people do by hand. Always go to the closest town you haven’t been to. It takes a moment, and it usually lands within a quarter or so of the shortest. Its weakness is the end. By then the only towns left are far apart, and the road home is long.

2-opt repairs a tour. Two roads that cross can always be swapped for two that don’t, and the swap is shorter. Take two roads A–B and C–D, and replace them with A–C and B–D. Then turn the stretch from B to C around, so the tour still joins up. Repeat while any swap saves distance. The result has no crossings, and it is usually within a few percent of the shortest.

Simulated annealing makes random changes instead. Sometimes it accepts a change that makes the tour longer. It does that less often as it “cools”. So it can get out of a tour that no single change improves.

Christofides’ method comes with a promise. On straight-line distances it is never more than one and a half times the shortest. It joins the towns by a minimum spanning tree. It pairs up the towns where the tree has an odd number of roads. Then it walks the result as an Euler circuit and skips towns it has already seen.

The shortest tour itself comes from shortestTour(weight:), which runs Held and Karp’s dynamic programming. It finds the best way to visit each subset of towns, ending at each town, and builds it up from smaller subsets.

Where it breaksTwice as many towns, a thousand times the work

Held–Karp’s table has an entry for every subset of towns, so each town added doubles it. Eleven towns are instant. Twenty need tens of megabytes. Thirty would need more memory than any computer has. The problem is NP-hard, and no known method finds the shortest tour quickly for every map. That is why the heuristics matter. Run on thousands of towns, the good ones are judged by how close they get.

The heuristics also need a sensible map. Christofides’ promise needs the triangle inequality, which says going direct is never longer than going through a third town. One-way streets, tolls or ferries can break it. Then the promise is gone, though the tour is still a tour.
