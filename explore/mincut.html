Minimum cut

Say itnah-gah-MOH-chee ee-bah-RAH-kee/naɡamotɕi ibaɾaki/

What’s the fewest cables you’d have to cut to split a network in two?

Example: eight offices joined by data links, each labelled with the number of cables in it. Cutting a link means cutting all its cables.

7 pairs to separate

To split the network, cut every cable between two groups of offices. Which split takes the fewest cuts? Press Step to separate one pair of offices at a time, as cheaply as possible.

Gomory–Hu tree so far

The fewest cables between any two offices is the lightest edge on the tree path between them.

Each step is one edge of the Gomory–Hu tree, in the order gomoryHuTree(capacity:) adds them, with its cut from minimumCut(between:and:). Click a link to add a cable; four goes back to one.

import AdjacencyListModule
import Flows
import GraphProtocols

let cables: [UndirectedEdge<String>: Int] = [
    UndirectedEdge("Ashford", "Bury"): 3,
    UndirectedEdge("Ashford", "Cobham"): 2,
    UndirectedEdge("Bury", "Cobham"): 3,
    UndirectedEdge("Bury", "Deal"): 2,
    UndirectedEdge("Cobham", "Deal"): 4,
    UndirectedEdge("Cobham", "Goole"): 1,
    UndirectedEdge("Deal", "Epsom"): 2,
    UndirectedEdge("Epsom", "Frome"): 3,
    UndirectedEdge("Epsom", "Goole"): 4,
    UndirectedEdge("Frome", "Goole"): 2,
    UndirectedEdge("Frome", "Hythe"): 3,
    UndirectedEdge("Goole", "Hythe"): 3,
]

let offices = UndirectedAdjacencyList<String> {
    for link in cables.keys.sorted() { link }
}

let cheapest = offices.minimumCut { cables[offices.edges[$0]]! }!
let fewest = cheapest.value  // 3
let cutOff = cheapest.sinkSide  // ["Goole", "Epsom", "Frome", "Hythe"]

let gomoryHu = offices.gomoryHuTree { cables[offices.edges[$0]]! }!
let pairs = Array(gomoryHu.tree.edges)  // [Bury–Ashford, Cobham–Bury, Deal–Cobham, Goole–Epsom, Epsom–Deal, Frome–Goole, Hythe–Frome]
let cuts = pairs.map { gomoryHu.minimumCut(between: $0.u, and: $0.v) }
let values = cuts.map(\.value)  // [5, 7, 7, 8, 3, 8, 6]

The ideaThe weakest place to split

A cut splits the vertices into two non-empty groups; its value is the total capacity of the edges between them, here the cables. A minimum cut is the cheapest such split. It is how fragile the network is: the least an attacker, a digger or a storm has to break to cut someone off. Often it just isolates the most weakly connected office; here it is the few links between two clusters.

To keep two particular offices apart, the cheapest cut equals the most data that can flow between them, the max-flow min-cut theorem from maximum flow. Gomory and Hu showed that n − 1 such flows answer every pair at once: they fit in a tree on the same offices, and the fewest cables between any two is the lightest edge on their tree path. The timeline builds that tree one edge at a time, by Gusfield’s method, as gomoryHuTree(capacity:) does, so the cheapest cut overall is its lightest edge.

When no pair is given, minimumCut(capacity:) finds the cheapest split directly, without any flows: Nagamochi and Ibaraki’s method orders the vertices by how tightly each is tied to those before it, and merges any two whose tie is at least the best cut seen so far, since a cheaper cut can’t separate them. That runs in O(nm log n).

Where it breaksCheapest isn’t always the split you want

The minimum cut loves to cut off one poorly connected vertex. That is right for measuring fragility, and wrong for finding two balanced halves: a split into roughly equal sides with few edges between them is a different, much harder problem (balanced partitioning), and community detection is usually what people mean by it.

Capacities must not be negative. On a directed network, minimumCut(capacity:) counts only the edges leaving one side, and uses Hao and Orlin’s method instead; to separate two given vertices, use minimumCut(from:to:capacity:).
