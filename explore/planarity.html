Planarity

Say itkoo-rah-TOV-skee/kuraˈtɔfskʲi/

Can three houses each get water, gas and power without any two pipes crossing?

What it’s forDrawing a graph with no crossings

A graph is planar when you can draw it on paper with no two edges crossing. A planarity test tells you whether such a drawing exists. If it does, you get the drawing. If it doesn’t, you get a small piece of the graph that proves it.

Reach for it when crossings cost something real, as with tracks on a circuit board or roads on a map. Many hard problems also get easier when the graph is planar, so it pays to know.

Counting edges is instant but only rules graphs out. The two full tests take time in step with the size of the graph. Ask for the proof only when you need it.

The ideaTwo small graphs are behind every failure

The drawing you start with doesn’t matter. The cube looks tangled as first drawn, yet planarLayout() finds a drawing of it with no crossings. What matters is whether some drawing exists.

The puzzle has no solution. Its graph is K₃,₃, where three vertices are each joined to the same other three. Five towns all joined to each other make K₅. In 1930 Kuratowski proved that these two are the only obstacles. A graph is planar exactly when it contains no copy of either. The copy may be stretched out, with extra stops along its paths. So a “no” always comes with a proof you can check by eye. findKuratowskiSubgraph() returns it, drawn in red.

A planar drawing splits the paper into faces, and the outside counts as one. For a connected planar graph, Euler’s formula says vertices − edges + faces = 2. Every face needs at least three edges round it. So a simple planar graph has at most 3n − 6 edges. That already rules out K₅, which has 10 edges, one more than 3 × 5 − 6 = 9.

isPlanar and planarEmbedding() run de Fraysseix and Rosenstiehl’s left-right test, built on depth-first search. findKuratowskiSubgraph() runs Boyer and Myrvold’s edge addition, which keeps the proof when it fails.

Where it breaksPlanar isn’t the same as easy to read

A planar layout avoids crossings, but it can squeeze vertices close together and stretch edges out. The cube’s layout shows this. For a drawing that shows a graph’s shape, crossings and all, use a force-directed layout. When a graph isn’t planar, finding the fewest crossings any drawing can have is much harder. No fast method is known.

Planarity is also a gift for other problems. Every planar graph can be coloured with four colours. That is the four-colour theorem.

In SwiftThe graph above, in Grafluent

import AdjacencyListModule
import GraphDrawing
import GraphProtocols
import Planarity

let places = ["House A", "House B", "House C", "Water", "Gas", "Power"]
let links = [
    UndirectedEdge("House A", "Water"),
    UndirectedEdge("House A", "Gas"),
    UndirectedEdge("House A", "Power"),
    UndirectedEdge("House B", "Water"),
    UndirectedEdge("House B", "Gas"),
    UndirectedEdge("House B", "Power"),
    UndirectedEdge("House C", "Water"),
    UndirectedEdge("House C", "Gas"),
    UndirectedEdge("House C", "Power"),
]
let added = 0

let graph = UndirectedAdjacencyList<String> {
    for place in places { place }
    for link in links.prefix(added) { link }
}
let planar = graph.isPlanar  // true
let witness = graph.findKuratowskiSubgraph()  // nil
let drawing = graph.planarLayout()  // 6 points on a grid, no crossings
let faces = graph.planarEmbedding()?.faceCount  // 0
