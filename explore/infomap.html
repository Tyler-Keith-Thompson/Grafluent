Infomap

A walker wanders a park’s footpaths at random. Which way of naming the clearings makes the story of the walk shortest?

What it’s forCommunities from where a walk lingers

Most community methods ask where the links are dense. Infomap asks where a random walker gets caught. It gives each module a name and each place a name inside its module, like area codes and local numbers, and measures how many bits per step it takes to tell the walk. Modules the walker rarely leaves make the telling short. The modules that make it shortest are the communities. The measure is the map equation, and its value the code length.

Reach for Infomap when flow is what matters: traffic, citations, money, where a link means something passes along it. It works on directed networks as naturally as undirected ones.

The ideaA two-level code for a random walk

Give every place a codeword, and the walk is a string of codewords. Short codewords for places visited often, as Huffman would, give the one-level cost. Now group the places into modules: a step inside a module spells only the place’s name within the module, which is shorter because the module is small; a step out spells the exit, the new module and the entrance. The map equation adds up the expected bits per step over the walk’s stationary distribution. Good modules trap the walk, so exits are rare and the inside names are short.

Infomap finds modules by a greedy search like Louvain’s, moving each place to the neighbouring module that most shortens the code, then merging modules into super-places and repeating. The start is random, so infomapCommunities(trials:using:) runs several trials from the generator you pass and keeps the shortest. codeLength(of:) scores any grouping, so the lab compares the modules with Louvain’s communities and with the two extremes: everything in one module, and every clearing on its own.

Where it breaksFlow where there is none

On a network where links don’t carry anything, the walk is a fiction, and modularity may fit the question better. Very sparse networks, or a star, trap no walk, and Infomap may leave everything in one module. The search is randomised: two runs can differ on a borderline place, so pass a seeded generator for a repeatable answer and raise the trials when it matters.

import AdjacencyListModule
import CommunityDetection
import GraphProtocols
import RandomGraphs

/// A park's footpaths: three clearings, each a knot of paths, joined by a few long trails.
let footways = [
    UndirectedEdge("A1", "A2"), UndirectedEdge("A1", "A3"), UndirectedEdge("A1", "A4"), UndirectedEdge("A2", "A3"),
    UndirectedEdge("A2", "A4"), UndirectedEdge("A3", "A4"),
    UndirectedEdge("B1", "B2"), UndirectedEdge("B1", "B3"), UndirectedEdge("B2", "B3"), UndirectedEdge("B2", "B4"),
    UndirectedEdge("B3", "B4"), UndirectedEdge("B4", "B5"), UndirectedEdge("B3", "B5"),
    UndirectedEdge("C1", "C2"), UndirectedEdge("C1", "C3"), UndirectedEdge("C2", "C3"), UndirectedEdge("C3", "C4"),
    UndirectedEdge("C2", "C4"),
    UndirectedEdge("A4", "B1"), UndirectedEdge("B5", "C1"), UndirectedEdge("A3", "C4"),
]

let trails = UndirectedAdjacencyList<String> {
    for footway in footways { footway }
}

let trials = 8

var generator = Xoshiro256StarStar(seed: 2)
let modules = trails.infomapCommunities(trials: trials, using: &generator)
let bits = trails.codeLength(of: modules)  // 2.96
let oneModule = trails.codeLength(of: [Array(trails.vertices)])  // 3.69
let apart = trails.codeLength(of: trails.vertices.map { [$0] })  // 5.69

let byModularity = trails.louvainCommunities()
let bitsByModularity = trails.codeLength(of: byModularity)  // 2.96
let q = trails.modularity(of: byModularity)  // 0.52
