Tortoise and hare

Keep clicking “Next” and the pages start repeating. Where does the loop begin, and how long is it, if you may only keep two bookmarks?

What it’s forFind a loop without remembering the way

Some sequences go on by one rule, where each value decides the next. Sooner or later such a sequence may start to repeat. The tortoise and hare methods find where the repeating starts and how long the loop is. They remember only two positions, however long the sequence runs.

Reach for them when the sequence is too long to store, such as the output of a random number generator. When everything fits in memory, simply marking each value you have seen is easier.

Both tortoise and hare methods use constant memory. That is their point. In the table, n is the number of pages.

The events come from lazy.floydCycleDetection(from:) or lazy.brentCycleDetection(from:).

The ideaA faster runner laps a slower one

In a functional graph every vertex has exactly one way out. It is a function from the vertices to themselves, here “the page Next opens”. Walking it from any start traces a shape like the Greek letter ρ. There is a tail of μ steps, then a loop of λ pages forever.

Floyd’s method keeps two positions. The tortoise moves one step a turn, and the hare moves two. Once both are on the loop, the hare gains one step a turn. So it must land on the tortoise.

Next, send the tortoise back to the start. A little arithmetic shows that the start and the meeting point are the same distance from the loop’s first page. So move both one step at a time. They meet at the loop’s first page, after μ steps. One more lap from there gives λ.

Brent’s method moves only the hare. The tortoise waits. Each time the hare has run a power of two steps without meeting it, the tortoise jumps to the hare, and the allowance doubles. When the hare comes back to the waiting tortoise, the steps since the jump are λ. A second pass, with the two runners λ apart, finds μ.

Where it breaksWhen memory isn’t the problem

Both methods find loops in sequences far too long to store. Pollard’s method for factoring numbers relies on this. When the graph is small and in memory, marking pages as you go is simpler. cycleDecomposition() finds every loop of a FunctionalGraph at once, in O(n).

Neither method works when a vertex has several ways out. For those graphs, a depth-first search finds a cycle.

In SwiftThe pages above, in Grafluent

import FunctionalGraphs
import GraphProtocols

// Pages A, B, C, … are 0, 1, 2, …; page i’s “Next” link opens page nextPage[i].
let nextPage = [1, 2, 3, 4, 5, 6, 7, 8, 4, 2, 9, 6]
let readingList = FunctionalGraph(successors: nextPage)

let floyd = Array(readingList.lazy.floydCycleDetection(from: 0))  // 17 events, ending step(4, 4), cycle(5)

let brent = Array(readingList.lazy.brentCycleDetection(from: 0))  // 26 events, ending step(4, 4), root(4, 4)
