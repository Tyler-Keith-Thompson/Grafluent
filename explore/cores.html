Cores and trusses

Who is at the tight centre of a group of friends, and who hangs on at the edge?

What it’s forFinding the dense centre of a network

The k-core is the largest group in which everyone has at least k friends inside the group. A person’s core number is the largest k whose core they are in. People with high core numbers sit at the tight centre. People with low ones hang on at the edge.

Reach for cores to find the dense heart of a large network, or to throw away the loose fringe before running something slower. They take time in step with the size of the network, so they work on millions of links.

Cores are the quickest and the loosest. Trusses demand shared friends, so they find tighter groups. Cliques demand every pair, which is often too strict for real data.

The ideaTake away whoever has too few friends, until nobody does

To find the k-core, remove everyone with fewer than k friends. Their friends now have fewer friends, so some of them may drop below k too. Keep removing until everyone left has at least k. What is left doesn’t depend on the order of removal. That is why “the” k-core makes sense.

Doing this for k = 1, 2, 3 and so on gives every core number. Batagelj and Zaveršnik do it in a single pass. They keep people in buckets by their current friend count. They always remove someone from the lowest bucket, and move each of that person’s friends down a bucket. This takes time in step with people plus friendships. coreNumbers() is that algorithm.

The greatest core number is the network’s degeneracy. It says how dense the densest part is. It also bounds other things. The graph can be coloured, so that no two joined vertices share a colour, with one more colour than its degeneracy. And the search on the cliques page goes in degeneracy order to stay fast.

The onion decomposition in the second lab peels a whole round at once and numbers the rounds. Each layer sits inside one core shell, everyone with the same core number, so the layers tell you more than the core numbers. Fay and Gus both have core number 3. But Fay is one layer deeper, because she only falls once Gus and Hal are gone.

A k-truss asks the same question of friendships instead of people. Keep only the friendships whose two people share at least k − 2 friends inside what is kept, so that each kept friendship and its shared friends make a group of k. A truss is always inside a core, and tighter. Take a long ring where each person has two friends. It is a 2-core, but it has no triangle, so it has no 3-truss. trussNumbers() peels friendships by how many triangles they are in, since each shared friend makes a triangle with the pair.

Where it breaksBig hubs are not the centre

Picture a person with dozens of friends who don’t know each other. Each friend has only one link, so they all go early, and the hub falls with them. Its core number is low. That is the point, because a core finds groups that hold together. But it means a core number doesn’t rank importance. For that, see PageRank or betweenness.

A core can also be in pieces. Two separate tight groups can both be in the 3-core, with nothing joining them. kCore(_:) lists the people. To see the groups, take the core as its own graph and ask for its connected components.

import AdjacencyListModule
import Cliques
import GraphProtocols

let ties = [
    UndirectedEdge("Ana", "Ben"), UndirectedEdge("Ana", "Cy"), UndirectedEdge("Ana", "Dee"),
    UndirectedEdge("Ana", "Eli"), UndirectedEdge("Ben", "Cy"), UndirectedEdge("Ben", "Dee"),
    UndirectedEdge("Ben", "Eli"), UndirectedEdge("Cy", "Dee"), UndirectedEdge("Cy", "Eli"),
    UndirectedEdge("Dee", "Eli"), UndirectedEdge("Fay", "Ana"), UndirectedEdge("Fay", "Ben"),
    UndirectedEdge("Fay", "Gus"), UndirectedEdge("Gus", "Ben"), UndirectedEdge("Gus", "Hal"),
    UndirectedEdge("Hal", "Fay"), UndirectedEdge("Hal", "Cy"), UndirectedEdge("Ivy", "Dee"),
    UndirectedEdge("Ivy", "Jo"), UndirectedEdge("Jo", "Eli"), UndirectedEdge("Kai", "Cy"),
    UndirectedEdge("Kai", "Lea"), UndirectedEdge("Lea", "Hal"), UndirectedEdge("Max", "Ivy"),
    UndirectedEdge("Ned", "Kai"), UndirectedEdge("Ola", "Lea"), UndirectedEdge("Pat", "Gus"),
]

let club = UndirectedAdjacencyList<String> {
    for tie in ties { tie }
}

let k = 3

let cores = club.coreNumbers()
let inner = cores.kCore(k)  // ["Ana", "Ben", "Cy", "Dee", "Eli", "Fay", "Gus", "Hal"]
let degeneracy = cores.degeneracy  // 4

In SwiftThe peeling, in Grafluent

import AdjacencyListModule
import Cliques
import GraphProtocols

let ties = [
    UndirectedEdge("Ana", "Ben"), UndirectedEdge("Ana", "Cy"), UndirectedEdge("Ana", "Dee"),
    UndirectedEdge("Ana", "Eli"), UndirectedEdge("Ben", "Cy"), UndirectedEdge("Ben", "Dee"),
    UndirectedEdge("Ben", "Eli"), UndirectedEdge("Cy", "Dee"), UndirectedEdge("Cy", "Eli"),
    UndirectedEdge("Dee", "Eli"), UndirectedEdge("Fay", "Ana"), UndirectedEdge("Fay", "Ben"),
    UndirectedEdge("Fay", "Gus"), UndirectedEdge("Gus", "Ben"), UndirectedEdge("Gus", "Hal"),
    UndirectedEdge("Hal", "Fay"), UndirectedEdge("Hal", "Cy"), UndirectedEdge("Ivy", "Dee"),
    UndirectedEdge("Ivy", "Jo"), UndirectedEdge("Jo", "Eli"), UndirectedEdge("Kai", "Cy"),
    UndirectedEdge("Kai", "Lea"), UndirectedEdge("Lea", "Hal"), UndirectedEdge("Max", "Ivy"),
    UndirectedEdge("Ned", "Kai"), UndirectedEdge("Ola", "Lea"), UndirectedEdge("Pat", "Gus"),
]

let club = UndirectedAdjacencyList<String> {
    for tie in ties { tie }
}

let onion = club.onionLayers()
let layers = (1 ... onion.layerCount).map { n in
    club.vertices.filter { onion.layer(of: $0) == n }
}  // [["Max", "Ned", "Ola", "Pat"], ["Ivy", "Jo", "Kai", "Lea"], ["Gus", "Hal"], ["Fay"], ["Ana", "Ben", "Cy", "Dee", "Eli"]]
