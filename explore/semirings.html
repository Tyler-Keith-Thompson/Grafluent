Semirings

Which route is quickest? Which carries the most data? Which is least likely to fail? Can one route finder answer all three?

What it’s forOne route finder, many questions

Route questions come in many kinds. Some ask for the quickest route, some for the widest, some for the most reliable. A semiring lets one shortest-path search answer all of them. You choose the question by choosing the semiring. The search stays the same.

Reach for one when you have a route question that isn’t about distance. You keep the speed of Dijkstra’s algorithm, and you write no new search.

A semiring search runs as fast as a search written by hand for the question. Its limits are the two promises under “Where it breaks” below.

Places are answered best first, the order Dijkstra’s algorithm settles them in. The numbers on the links belong to the question.

The ideaTwo moves, with different arithmetic

Look at Mill under Quickest. Data can arrive from North or from South. Through North it takes 4 + 3 = 7 minutes. Through South it takes 2 + 2 = 4 minutes. The quicker route wins, so Mill gets 4.

Now look at Mill under Widest. A route carries only as much as its narrowest link. Through North that is the smaller of 100 and 80, so 80. Through South it is the smaller of 40 and 30, so 30. The wider route wins, so Mill gets 80.

Both answers used the same two moves. The first move extends a route by one more link. The second chooses between two routes to the same place. Only the arithmetic changed. Quickest extends with + and chooses with min. Widest extends with min and chooses with max.

Each row also needs two special values. No route loses every choice, because any real route beats it. Already there is the route with no links. Extending by it changes nothing, like adding 0 minutes or multiplying by a chance of 1.

Name itThat pair is a semiring

A semiring is a pair of moves like these, together with the two special values. The moves follow the same rules as × and + on ordinary numbers. The order of a choice doesn’t matter. Extending by no route gives no route. And extending the better of two routes gives the same result as extending both and then choosing. That last rule lets the search decide once at each place, without keeping every route.

In Grafluent this is the Semiring protocol. times(_:) extends and plus(_:) chooses. zero is no route, and one is already there. The five rows above are TropicalSemiring, BottleneckSemiring, ViterbiSemiring, BooleanSemiring and CountingSemiring. In the code panel, only the wrapper around each link’s value changes.

Where it breaksDijkstra needs two more promises

Dijkstra settles a place for good once nothing better can still arrive. That needs two promises. The first is that extending never makes a route better. So there are no negative minutes, and no chance above 1. Grafluent checks each weight against one. The second is that choosing keeps one of the two routes. Min, max and or all do. A semiring whose choice always keeps one of the two is called selective. That is Grafluent’s SelectiveSemiring, and it is what dijkstraShortestPaths takes.

Counting routes breaks the second promise. Choosing adds the two counts, so no single route wins. A place can’t be settled until every way into it is known. That works when no link loops back, as in this network. dagShortestDistances runs Mohri’s algorithm, which visits the places in an order where every link points forward. With a loop there would be infinitely many routes to count.

In SwiftThe network above, in Grafluent

import AdjacencyListModule
import GraphProtocols
import Semirings
import ShortestPaths

let connections = [
    (edge: DirectedEdge(from: "Server", to: "North"), minutes: 4, megabits: 100, up: 0.99),
    (edge: DirectedEdge(from: "Server", to: "South"), minutes: 2, megabits: 40, up: 0.95),
    (edge: DirectedEdge(from: "North", to: "Mill"), minutes: 3, megabits: 80, up: 0.98),
    (edge: DirectedEdge(from: "South", to: "Mill"), minutes: 2, megabits: 30, up: 0.90),
    (edge: DirectedEdge(from: "North", to: "Bank"), minutes: 7, megabits: 90, up: 0.97),
    (edge: DirectedEdge(from: "South", to: "Bank"), minutes: 6, megabits: 60, up: 0.99),
    (edge: DirectedEdge(from: "Mill", to: "Bank"), minutes: 1, megabits: 50, up: 0.95),
    (edge: DirectedEdge(from: "Mill", to: "Dock"), minutes: 5, megabits: 70, up: 0.90),
    (edge: DirectedEdge(from: "Bank", to: "Dock"), minutes: 2, megabits: 100, up: 0.99),
    (edge: DirectedEdge(from: "Bank", to: "Farm"), minutes: 6, megabits: 20, up: 0.80),
    (edge: DirectedEdge(from: "Dock", to: "Farm"), minutes: 3, megabits: 60, up: 0.97),
]

let network = AdjacencyList<String> {
    for connection in connections { connection.edge }
}
let link = Dictionary(uniqueKeysWithValues: connections.map { ($0.edge, $0) })

let best = network.dijkstraShortestPaths(from: "Server") { TropicalSemiring(link[network.edges[$0]]!.minutes) }
let farm = best.distance(to: "Farm")  // 10 min
