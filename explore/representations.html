Storing a graph

How does a computer keep a graph in memory, and why does it matter which way?

Example: four friends and who follows whom. Ana follows Ben and Cy. Ben follows Cy, Cy follows Ana, and Dee follows Cy. That makes a directed graph with four vertices and five edges. Add or remove a follow, and all three forms change together.

Ana is picked. Click someone else to add or remove “Ana follows them”, or click Ana again to let go.

In SwiftThe friends above, in Grafluent

import AdjacencyListModule
import AdjacencyMatrixModule
import CompressedSparseRowModule
import GraphProtocols
import LabeledGraphs

let people = ["Ana", "Ben", "Cy", "Dee"]
let arrows = [
    ("Ana", "Ben"),
    ("Ana", "Cy"),
    ("Ben", "Cy"),
    ("Cy", "Ana"),
    ("Dee", "Cy"),
]

let follows = AdjacencyList<String> {
    for name in people { name }
    for (who, whom) in arrows { DirectedEdge(from: who, to: whom) }
}
let rows = people.map { Array(follows.successors(of: $0)) }
let matrix = LabeledGraph<String, AdjacencyMatrix>(follows)
let csr = LabeledGraph<String, CompressedSparseRow>(follows)

let anaRow = rows[0]  // ["Ben", "Cy"]
let anaToBen = matrix.contains(edge: DirectedEdge(from: "Ana", to: "Ben"))  // true
let offsets = csr.base.offsets  // [0, 2, 3, 4, 5]
let targets = csr.base.targets.map { csr.vertex(atIndex: $0) }  // ["Ben", "Cy", "Cy", "Ana", "Cy"]

Adjacency listA row of neighbours per vertex

For each vertex, keep a list of the vertices its edges point to. To ask “who does Ana follow?”, look up Ana’s list. The lists grow only with the edges that exist. So they suit big graphs where each vertex has just a few neighbours, and most real graphs are like that. Adding and removing edges is cheap. Grafluent’s AdjacencyList also keeps each vertex’s incoming edges, so “who follows Cy?” is just as quick.

Adjacency matrixA square for every pair

Make a grid with one row and one column per vertex. Put a 1 in row r, column c when there is an edge from r to c, and a 0 otherwise. Rows say who follows. Columns say who is followed. To read it, pick a row and go across. Ana’s row has 1s under Ben and Cy, because Ana follows them. To find who follows Cy, read down Cy’s column instead.

In an undirected graph every edge counts both ways. So the grid is a mirror image across its diagonal. Switch the example to friends to see it.

The matrix answers “is there an edge from r to c?” in one look-up, however big the graph. The price is space. It needs a square for every pair of vertices, edge or no edge. Four friends need 16 squares. A million need a trillion, and almost all of them are 0. Grafluent’s AdjacencyMatrix stores each square as one bit.

Compressed sparse rowTwo plain arrays

Take the adjacency list and pack every row end to end into one array of targets. A second, shorter array of offsets records where each vertex’s run starts. Ana’s run starts at 0 and Ben’s at 2, so Ana’s targets are positions 0 and 1. The last offset marks the end. So a vertex’s run always ends where the next one starts.

Two plain arrays are as compact as a graph gets, and a processor walks them very fast. The catch is that you can’t add an edge without rebuilding the whole thing.

When to use whichOne answer, three speeds

FormWhen to useIs there an edge?SpaceWeakness
Adjacency list (AdjacencyList)The default, and any graph that changesOne hash look-upGrows with the edgesA little slower to walk than two arrays
Adjacency matrix (AdjacencyMatrix)Small graphs, or ones where most pairs are connectedOne look-upOne bit for every pairHuge for a big graph with few edges
Compressed sparse row (CompressedSparseRow)A large graph you build once and study many timesA binary search of one rowGrows with the edges, and nothing wastedCan’t change without a rebuild

The matrix and compressed sparse row number their vertices 0, 1, 2 and so on. A LabeledGraph puts names on those numbers, which is how this page keeps “Ana” and “Ben”. Every algorithm on this site runs on all three forms. The answer is the same. Only the speed and the memory differ.
