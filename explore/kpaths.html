k shortest paths

Say itYEN/jɛn/

The quickest route is blocked. What’s the next best way across town, and the one after that?

In SwiftThe town above, in Grafluent

import AdjacencyListModule
import GraphProtocols
import ShortestPaths

let driveMinutes: [UndirectedEdge<String>: Int] = [
    UndirectedEdge("Home", "Mill"): 6,
    UndirectedEdge("Home", "Bridge"): 8,
    UndirectedEdge("Home", "Square"): 14,
    UndirectedEdge("Mill", "Square"): 4,
    UndirectedEdge("Mill", "Museum"): 5,
    UndirectedEdge("Bridge", "Square"): 5,
    UndirectedEdge("Bridge", "Market"): 6,
    UndirectedEdge("Square", "Museum"): 6,
    UndirectedEdge("Square", "Park"): 6,
    UndirectedEdge("Square", "Harbor"): 9,
    UndirectedEdge("Museum", "Harbor"): 5,
    UndirectedEdge("Market", "Park"): 7,
    UndirectedEdge("Harbor", "Park"): 3,
    UndirectedEdge("Harbor", "Stadium"): 6,
    UndirectedEdge("Park", "Stadium"): 5,
]

let crosstown = UndirectedAdjacencyList<String> {
    for road in driveMinutes.keys.sorted() { road }
}

let start = "Home"
let goal = "Stadium"
let count = 8

let routes = crosstown.shortestSimplePaths(from: start, to: goal) { driveMinutes[crosstown.edges[$0]]! }
let firstFew = Array(routes.prefix(count))  // 8 routes
let minutes = firstFew.map(\.distance)  // [21, 22, 24, 24, 25, 25, 25, 26]
let quickest = firstFew.first?.path.vertices ?? []  // ["Home", "Mill", "Square", "Park", "Stadium"]

The ideaEvery new route is a detour off an old one

The quickest route is one Dijkstra search. For the second, notice that any other route agrees with the first for a while, maybe only at Home, and then turns off somewhere. So try each stop of the first route as the turning point: keep the stretch before it, forbid the road the first route took from there, and search for the quickest way to finish without going back through the kept stretch. Each turning point gives one candidate. The cheapest candidate is the second route.

Yen’s algorithm repeats this. After route k is found, it tries every turning point along route k, forbidding at each one the next road of every earlier route that shares the same opening, so no route can come out twice. Candidates pile up in a priority queue, and the cheapest one is always the next route. Lawler’s refinement skips the turning points before where route k itself turned off, since those were tried already. On the map, the blue line is the earlier route a new one shares its opening with, and the yellow stretch is the detour.

In Grafluent, shortestSimplePaths(from:to:weight:) returns a lazy sequence: nothing past the first route is searched until you ask for it, so prefix(k) costs only what k routes cost. Without a weight, it counts roads instead of minutes.

Where it breaksNear-copies, and a search per stop

The next quickest route is usually the quickest with one small wiggle: a block around the corner and back. A route planner offering alternatives wants routes that differ by more than that, and filters the list (for example, dropping routes that share most of their roads with one already shown) or penalises roads already used and searches again. Yen gives the true ranking; deciding which alternatives are worth showing is a separate choice.

Each new route costs up to one shortest-path search per stop on the route before it, so asking for thousands of routes on a large map is slow. Weights must not be negative: the searches are Dijkstra’s. And the routes are simple, never visiting a place twice; when repeats are allowed, Eppstein’s algorithm lists the k shortest walks much faster.
