Knowledge graphs

A language model, the kind of AI behind chat assistants, read a few paragraphs and wrote down fourteen claims, spelling Ada Lovelace three ways. Which of them belong in the prompt for a question about her and the Analytical Engine?

What it’s forFacts as a graph, and the right few back out

A knowledge graph stores facts as arrows between entities, the people, places and things the facts are about. Each arrow is labelled with a relation, such as Ada Lovelace –worked with→ Charles Babbage. Written out, a fact is a triple of subject, relation and object. Retrieval that works from such a graph is often called GraphRAG, for retrieval-augmented generation. It looks the facts up and hands them to the model. It answers a question by finding the entities it names, taking the facts around them and writing those facts into the prompt, the text handed to the model with the question. The graph side is four small steps: merge the duplicate entities, rank the entities from the question, cut the neighbourhood to a budget, and write it out.

Reach for it when a question needs facts that sit several hops apart, which a plain search over passages tends to miss, or when the same entity is named in many documents and the answer should join them.

Ranking from the question’s entities favours facts on the paths between them; a degree cut favours hubs. Community summaries answer broad questions, and passage search answers narrow ones.

Each stage is one call: quotient(of:byKey:), pageRank(personalization:), egoGraphView(of:radius:undirected:maximumVertexCount:priority:) and writeEdgeList(to:columns:delimiter:edgeAttributes:).

The ideaFour calls, one graph

The relations live in an edge map, a table from each edge to its label, on a directed pseudograph, a directed graph that allows several edges between the same pair and self-loops, so two claims about the same pair stay separate edges with their own relation. Merging glues every vertex with the same key into one vertex and keeps all their edges, a quotient graph. quotient(of:byKey:) makes one vertex of every spelling that maps to the same canonical name, the one agreed spelling, and the page rebuilds the graph from those names so the relations come along. Ranking is personalised PageRank, pageRank(personalization:), with the question’s entities as the places the random reader keeps jumping back to, so entities on the paths between them score high and far corners score low. Retrieval is egoGraphView from the question’s entities, two hops out, ignoring the arrows’ direction and keeping the best-ranked entities when the budget runs out. Writing is writeEdgeList with the relation as a column and a delimiter that allows spaces in names: one line per fact, subject, object and relation.

Where it breaksThe key, and the budget

The merge is only as good as the key. A key that maps two different people to one name joins their facts, and one that misses a spelling leaves a duplicate with its own facts; in practice the key comes from an entity-resolution step, one that works out which names mean the same thing, and the quotient applies it. The budget is a count of entities, not of facts, so a hub inside the budget brings every relation it has. And personalised PageRank ranks by structure alone: a fact that matters to the question but sits three hops away stays out, which is where community summaries help.

In SwiftThe claims, in Grafluent

import Centrality
import GraphFormats
import GraphOperations
import GraphProtocols
import Multigraphs

/// Facts pulled out of a few paragraphs as subject, relation, object. The extractor spelled some
/// names more than one way.
let claims: [(subject: String, relation: String, object: String)] = [
    ("Ada Lovelace", "wrote notes on", "Analytical Engine"), ("A. Lovelace", "daughter of", "Lord Byron"),
    ("Lovelace, Ada", "corresponded with", "Charles Babbage"), ("Charles Babbage", "designed", "Analytical Engine"),
    ("Babbage", "designed", "Difference Engine"), ("Analytical Engine", "read", "Punched cards"),
    ("Punched cards", "came from", "Jacquard loom"), ("Lord Byron", "wrote", "Poetry"),
    ("Lord Byron", "died in", "Greece"), ("Difference Engine", "tabulated", "Logarithms"),
    ("C. Babbage", "fellow of", "Royal Society"), ("Royal Society", "once led by", "Isaac Newton"),
    ("Alan Turing", "built on", "Analytical Engine"), ("Alan Turing", "worked at", "Bletchley Park"),
]

/// One spelling per entity: the key that merges duplicates.
func canonicalName(_ name: String) -> String {
    switch name {
    case "A. Lovelace", "Lovelace, Ada": "Ada Lovelace"
    case "Babbage", "C. Babbage": "Charles Babbage"
    default: name
    }
}

let spellings = DirectedPseudograph<String> {
    for claim in claims { DirectedEdge(from: claim.subject, to: claim.object) }
}
let merged = DirectedPseudograph<Int>.quotient(of: spellings, byKey: canonicalName)
let entities = merged.vertexCount  // 14

/// The knowledge graph on canonical names, each relation kept in an edge map.
let (knowledgeGraph, relationOf): (DirectedPseudograph<String>, EdgeMap<String>) = {
    var graph = DirectedPseudograph<String>()
    let relation = graph.addEdgeMap(default: "")
    for claim in claims {
        _ = graph.insert(canonicalName(claim.subject))
        _ = graph.insert(canonicalName(claim.object))
        let position = graph.insert(edge: DirectedEdge(from: canonicalName(claim.subject), to: canonicalName(claim.object)))
        graph[relation, ofEdgeAt: position] = claim.relation
    }
    return (graph, relation)
}()

let budget = 7

let ranks = try knowledgeGraph.pageRank(personalization: { questionSeeds.contains($0) ? 1 : 0 })
let nearby = knowledgeGraph.egoGraphView(of: questionSeeds, radius: 2, undirected: true, maximumVertexCount: budget) { ranks.score(of: $0) }
let kept = Array(nearby.vertices)  // ["Ada Lovelace", "Analytical Engine", "Lord Byron", "Charles Babbage", "Punched cards", "Jacquard loom", "Alan Turing"]
var prompt = ""
try nearby.writeEdgeList(to: &prompt, columns: ["relation"], delimiter: "|") { [("relation", .string(knowledgeGraph[relationOf, ofEdgeAt: $0]))] }
