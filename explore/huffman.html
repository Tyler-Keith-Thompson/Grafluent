Huffman coding

If common letters got shorter codes, how short could a sentence get?

Example: “she sells sea shells”, or anything you type. Stored as plain text, every letter takes 8 bits. A Huffman code gives each letter its own string of bits. Common letters get short ones, and rare letters get long ones.

What it’s forThe shortest code, one letter at a time

Huffman coding finds the shortest way to write a message when each letter gets its own code. Reach for it to compress text or any stream of symbols whose counts you know. Formats such as gzip, PNG and JPEG use it as their last step.

The ideaCodes are paths in a tree

Codes of different lengths have a catch. Say “e” is 0 and “s” is 01. Does 01 mean “s”, or “e” and then something starting with 1? The fix is a prefix-free code, where no code word starts another.

Such codes are exactly the leaves of a binary tree. Go left for 0 and right for 1, and stop at a letter. A letter’s code length is its depth in the tree. So the coded sentence costs the sum of count × depth over the letters.

Huffman’s insight, from 1952, is to build the cheapest such tree from the bottom. The two rarest letters can always sit deepest, side by side, in some best tree. So join them under a new node, whose weight is their total count. Treat that node as one letter, and repeat. Each join adds one bit to every letter beneath it. It always joins the two lightest, which is why no prefix-free code is shorter. With the letters sorted once, two queues make every join take constant time.

Where it breaksWhole bits, one letter at a time

Each letter gets at least one whole bit. Take text that is almost all one letter, such as “aaaaaaab”. It still needs a bit a letter, though it carries far less information than that. Arithmetic coding can spend fractions of a bit.

Huffman also looks at letters one at a time. So it can’t notice that “sea” and “shells” repeat. Dictionary methods such as LZ77 catch that. Formats like gzip run those first, and Huffman after.

The tree, or the counts, must also travel with the message so it can be decoded. On a short sentence like this one, that costs more than it saves. Shannon’s entropy sets a limit that no code can beat. Huffman always comes within one bit a letter of it.

import Trees

let text = "she sells sea shells"

var counts: [Character: Int] = [:]
for letter in text { counts[letter, default: 0] += 1 }
let letters = counts.keys.sorted { (counts[$1]!, $0) < (counts[$0]!, $1) }

let tree = BinaryTree<Int>.huffman(weights: letters.map { counts[$0]! })
let size = tree.vertexCount  // 11

var codes: [Character: String] = [:]
for (leaf, letter) in letters.enumerated() {
    var word = "", v = leaf
    while let parent = tree.parent(of: v) {
        word = (tree.left(of: parent) == v ? "0" : "1") + word
        v = parent
    }
    codes[letter] = word.isEmpty ? "0" : word
}
let bits = text.reduce(0) { $0 + codes[$1]!.count }  // 49
let plain = 8 * text.count  // 160
