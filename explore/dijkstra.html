Dijkstra’s algorithm

Say itDIKE-struh/ˈdɛikstra/

What’s the quickest walk from your front door to every other place in town?

What it’s forQuickest routes from one place

Dijkstra’s algorithm finds the quickest route from one starting place to every other place. Each street has a cost, such as minutes or kilometres. No cost may be negative.

Reach for it for road maps, network routing, and any route question where steps cost different amounts. When every step costs the same, breadth-first search is simpler. When some costs are negative, use Bellman–Ford.

Dijkstra is the usual choice for one start and costs of zero or more. It is fast, and it finds every place’s route in one run. In the table, n is the number of places and m the number of streets.

The ideaAlways settle the nearest unsettled place

Keep a best guess for every place. Where you are gets zero minutes, and everywhere else gets infinity. Then repeat one move. Take the frontier place with the smallest guess and call it settled. Check each street out of it. If going through it reaches a neighbour sooner, lower that neighbour’s guess.

Why can the smallest guess be trusted? Any other walk to that place must leave the settled region through some frontier place. Every frontier place is already at least that far away. Streets only add time, so a detour can’t come back quicker. That short argument is the whole proof. It is also where the algorithm breaks.

Where it breaksA street that gives you time back

Give one edge a negative weight, like a shortcut that somehow saves three minutes. Now a detour can come back quicker, and the argument fails. In this graph, Dijkstra settles A at 2 before it ever looks at B. The cheaper route S → B → A costs 4 − 3 = 1, but it arrives too late.

Dijkstra’s answer for A2settled before B was looked at
The true cheapest1S → B → A, 4 − 3
let cost: [DirectedEdge<String>: Int] = [
    DirectedEdge(from: "S", to: "A"): 2,
    DirectedEdge(from: "S", to: "B"): 4,
    DirectedEdge(from: "B", to: "A"): -3,
]
let graph = AdjacencyList<String> {
    for edge in cost.keys { edge }
}
let routes = graph.bellmanFordShortestPaths(from: "S") { cost[graph.edges[$0]]! }
let toA = routes?.distance(to: "A")  // 1
let stops = routes?.path(to: "A").map(Array.init)  // ["S", "B", "A"]

Grafluent refuses to give that wrong answer. dijkstraShortestPaths stops with a precondition failure on a negative weight. Use bellmanFordShortestPaths instead. It is slower, because it keeps checking every edge again. That is what lets it handle negative weights.

In SwiftThe town above, in Grafluent

import AdjacencyListModule
import GraphProtocols
import ShortestPaths

let minutes: [UndirectedEdge<String>: Int] = [
    UndirectedEdge("Home", "Bakery"): 4,
    UndirectedEdge("Home", "Park"): 6,
    UndirectedEdge("Bakery", "Park"): 3,
    UndirectedEdge("Bakery", "School"): 7,
    UndirectedEdge("Park", "Library"): 5,
    UndirectedEdge("School", "Library"): 4,
    UndirectedEdge("School", "Café"): 6,
    UndirectedEdge("Library", "Café"): 3,
    UndirectedEdge("Library", "Station"): 8,
    UndirectedEdge("Café", "Station"): 5,
    UndirectedEdge("Park", "Market"): 6,
    UndirectedEdge("Market", "Station"): 4,
    UndirectedEdge("Library", "Market"): 7,
]

let town = UndirectedAdjacencyList<String> {
    for street in minutes.keys.sorted() { street }
}

let start = "Home"
let goal = "Station"

let events = Array(town.lazy.dijkstra(from: start) { minutes[town.edges[$0]]! })  // 63 events

let walks = town.dijkstraShortestPaths(from: start) { minutes[town.edges[$0]]! }
let distance = walks.distance(to: goal)  // 16
let stops = walks.path(to: goal).map(Array.init)  // ["Home", "Park", "Market", "Station"]
