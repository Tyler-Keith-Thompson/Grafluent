Dijkstra’s algorithm

Say itDIKE-struh/ˈdɛikstra/

What’s the quickest walk from your front door to every other place in town, when no street takes less than no time at all?

Example: eight places in a small town, with walking minutes on each street.

import AdjacencyListModule
import GraphProtocols
import ShortestPaths

let minutes: [UndirectedEdge<String>: Int] = [
    UndirectedEdge("Home", "Bakery"): 4,
    UndirectedEdge("Home", "Park"): 6,
    UndirectedEdge("Bakery", "Park"): 3,
    UndirectedEdge("Bakery", "School"): 7,
    UndirectedEdge("Park", "Library"): 5,
    UndirectedEdge("School", "Library"): 4,
    UndirectedEdge("School", "Café"): 6,
    UndirectedEdge("Library", "Café"): 3,
    UndirectedEdge("Library", "Station"): 8,
    UndirectedEdge("Café", "Station"): 5,
    UndirectedEdge("Park", "Market"): 6,
    UndirectedEdge("Market", "Station"): 4,
    UndirectedEdge("Library", "Market"): 7,
]

let town = UndirectedAdjacencyList<String> {
    for street in minutes.keys.sorted() { street }
}

let start = "Home"
let goal = "Station"

let events = Array(town.dijkstraSearch(from: start) { minutes[town.edges[$0]]! })  // 63 events

let walks = town.dijkstraShortestPaths(from: start) { minutes[town.edges[$0]]! }
let distance = walks.distance(to: goal)  // 16
let stops = walks.path(to: goal).map(Array.init)  // ["Home", "Park", "Market", "Station"]

The ideaAlways settle the nearest unsettled place

Keep a best guess for every place: zero minutes for where you are, infinity for everywhere else. Then repeat one move: take the frontier place with the smallest guess, call it settled, and check each street out of it. If walking through it gets you to a neighbour sooner, lower that neighbour’s guess.

Why can the smallest guess be trusted? Any other walk to that place would have to leave the settled region through some frontier place, and every frontier place is already at least that far. Streets only add time, so a detour can’t come back quicker. That one sentence is the whole proof, and it is also where the algorithm breaks.

Where it breaksA street that gives you time back

Give one edge a negative weight, like a shortcut that somehow saves three minutes, and the argument above fails: a detour can now come back quicker. Here Dijkstra settles A at 2 before it ever looks at B, so the cheaper route S → B → A, costing 4 − 3 = 1, arrives too late.

Dijkstra’s answer for A2settled before B was looked at
The true cheapest1S → B → A, 4 − 3
let cost: [DirectedEdge<String>: Int] = [
    DirectedEdge(from: "S", to: "A"): 2,
    DirectedEdge(from: "S", to: "B"): 4,
    DirectedEdge(from: "B", to: "A"): -3,
]
let graph = AdjacencyList<String> {
    for edge in cost.keys { edge }
}
let routes = graph.bellmanFordShortestPaths(from: "S") { cost[graph.edges[$0]]! }
let toA = routes?.distance(to: "A")  // 1
let stops = routes?.path(to: "A").map(Array.init)  // ["S", "B", "A"]

Grafluent refuses to give that wrong answer: dijkstraShortestPaths stops with a precondition failure on a negative weight. Use bellmanFordShortestPaths instead. It is slower because it keeps re-checking every edge, and that is exactly what lets it handle negative weights.
