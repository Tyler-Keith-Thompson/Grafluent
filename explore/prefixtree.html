Prefix tree

You type “ca”. Which words could you mean, and how does the search box find them so fast?

Example: nine short words. Each vertex of the tree is a prefix of some word, and each edge adds one letter. The words that start with what you typed all hang below one vertex.

Add “dove”. “do” is already in the tree, so it takes 2 new vertices. Its last vertex is marked as a word. The tree has 14 vertices for 30 letters.

a word added

Each step is prefixTree(of:) on one more word. Suggestions come from the tree as it stands, so type while stepping to see them appear.

What it’s forEvery word that starts this way

A prefix tree finds every stored word that starts with what you typed. The time depends on how much you typed, not on how many words are stored. Reach for it for autocomplete, spell checkers and routing tables.

The ideaShare the beginnings

A prefix tree, or trie, stores a set of words so that words with the same beginning share it. The root is the empty prefix. To add a word, walk down from the root letter by letter. Follow an edge where one already exists, and make a new vertex where none does. Mark the vertex where the word ends. Adding “cart” after “car” and “card” costs one new vertex, because “car” is already there.

Looking up is the same walk. Follow the letters typed. If an edge is missing, no word starts that way. Otherwise every marked vertex below the one you reached is a word with that beginning. The walk costs the length of what you typed, however many words the list holds. Listing the suggestions costs the size of the part below.

prefixTree(of:) builds one from any sequences of hashable symbols, not just words. Lists of moves, paths in a file system and IP address bits all work. The tree is an Arborescence on vertex numbers. It records the symbol of each edge and the vertex where each sequence ends.

For a list that never changes, a sorted array is often just as good. A prefix tree pays off when the words change or the lookups are many.

Where it breaksMany vertices, and only exact beginnings

One vertex per distinct prefix adds up. A large dictionary has millions of them, mostly in long single-file chains near the leaves. A compressed trie merges each chain into one edge labelled with a whole string.

A prefix tree also finds only words that start exactly with what was typed. A real search box ranks suggestions by how often people choose them, and it forgives typos. That needs edit-distance search or a different index altogether.

In SwiftThe words above, in Grafluent

import GraphProtocols
import Trees

let words = ["car", "card", "care", "cart", "cat", "do", "dog", "dot", "dove"]
let added = 9
let typed = "ca"

let tree = prefixTree(of: words.prefix(added))

var node: Int? = 0
for letter in typed {
    node = node.flatMap { at in
        tree.arborescence.children(of: at).first { tree.symbol(ofEdgeAt: $0 - 1) == letter }
    }
}
let ends = node.map { at in
    tree.arborescence.preorder.filter { tree.isSequenceEnd($0) && ($0 == at || tree.arborescence.isAncestor(at, of: $0)) }
} ?? []
let suggestions = ends.map { words[tree.sequenceEnds.firstIndex(of: $0)!] }  // ["car", "card", "care", "cart", "cat"]
