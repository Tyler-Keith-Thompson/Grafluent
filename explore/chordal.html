Chordal graphs

Does every loop of four or more friends have a shortcut through it?

What it’s forSpotting graphs where hard problems turn easy

Go round a loop of friends, each friends with the next. A chord is a friendship between two of them who aren’t next to each other on the loop. It is a shortcut across. A graph is chordal when every loop of four or more has one. A loop without one is a hole.

Chordal graphs are worth spotting because many hard problems turn easy on them. The largest clique, the fewest colours and the largest independent set all take linear time. They also come up in sparse matrix solvers, and in schedules where time slots overlap.

The ideaTaking people away one at a time

Checking every loop would take forever, because there can be exponentially many. Chordal graphs have another description that is quick to check. A vertex is simplicial when its neighbours all know each other. Every chordal graph has one. Take it away, and what is left is still chordal, so it has another. The order this gives is a perfect elimination ordering. A graph has one exactly when it is chordal.

Finding the order is the clever part. A maximum cardinality search always visits next the vertex with the most visited neighbours. Tarjan and Yannakakis showed that it visits a chordal graph in the reverse of a perfect elimination ordering. So one search and one check decide the question, in time in step with vertices plus edges. That is isChordal.

Rose, Tarjan and Lueker’s lexicographic breadth-first search works the same way with a finer tie-break. It is the starting point for recognising other families of graphs.

Following a perfect elimination ordering gives the largest clique, a colouring with the fewest colours and the largest independent set. Sparse matrix solvers add “fill-in” edges to make a matrix’s graph chordal. Interval graphs, which show which time slots overlap, are always chordal.

Where it breaksA hole is the proof

When the test fails, it says no but not why. findHole() gives the why. It returns a loop of four or more with no shortcut, which anyone can check by eye. Finding it is slower than the plain test, because it searches around the vertices where the test failed.

Making a graph chordal by adding the fewest edges is called the minimum fill-in problem, and it is NP-hard. Any elimination order gives some chordal graph. That is why sparse solvers spend effort choosing a good order, and don’t look for the best one.

import AdjacencyListModule
import Cliques
import GraphProtocols
import Traversal

let acquaintances = [
    UndirectedEdge("Ana", "Ben"), UndirectedEdge("Ben", "Cy"), UndirectedEdge("Cy", "Dee"),
    UndirectedEdge("Dee", "Eli"), UndirectedEdge("Eli", "Fay"), UndirectedEdge("Fay", "Ana"),
    UndirectedEdge("Ana", "Cy"), UndirectedEdge("Ana", "Dee"), UndirectedEdge("Ana", "Eli"),
    UndirectedEdge("Cy", "Gus"), UndirectedEdge("Dee", "Gus"),
    UndirectedEdge("Eli", "Hal"), UndirectedEdge("Fay", "Hal"),
]

let removed = []

let friends = UndirectedAdjacencyList<String> {
    for pair in acquaintances where !removed.contains(pair) { pair }
}

let chordal = friends.isChordal  // true
let ordering = friends.perfectEliminationOrdering()  // ["Ben", "Gus", "Cy", "Dee", "Hal", "Fay", "Eli", "Ana"]
let hole = friends.findHole()?.vertices  // nil
