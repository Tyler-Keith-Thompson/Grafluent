Centre and diameter

Where should the county put its ambulance station, and how long is the longest drive it could face?

What it’s forFinding the middle and the far ends of a network

A village’s eccentricity is the distance to the village farthest from it. The smallest eccentricity anywhere is the network’s radius, and the villages that have it are its centre. The largest eccentricity is the diameter, and the villages that have it are the periphery.

Reach for these when you place something that must be near everyone, when you want to know the worst case for a delivery, or when you want one number for how spread out a network is. They work by hops, or by any weight such as minutes or metres.

The centre minimises the worst trip. The centroid minimises the average one. They are often the same village, and often not.

eccentricities() measures every village at once with a shortest-path search from each. The page shows one search per step.

The ideaOne shortest-path search from each place

From each village, run a shortest-path search to every other. The largest distance it finds is that village’s eccentricity. If some village cannot be reached at all, the eccentricity is infinite, written nil here. Do this from every village, and the radius, the diameter, the centre and the periphery all fall out of the list. eccentricities() does the searches and keeps the list; radius(), diameter(), center() and periphery() read it.

By hops the search is breadth-first and costs time in step with the roads. By minutes it is Dijkstra’s. Either way there is one search per village, so a county of n villages costs n searches. diameterPath() returns the longest of all the shortest drives, with its stops.

In the county, four villages tie for the centre by hops: Cedar, Dale, Glen and Holt, each three roads from its farthest village. By minutes only Glen is the centre, 19 minutes from its farthest, because the short Cedar–Glen road and the long Elm–Fir road change which villages are far. Ash and Fir are the periphery either way.

Where it breaksOne search per place adds up

A network of a million places needs a million searches, which is too slow. For a rough diameter, search from one place, then from the farthest place that search found, and take the larger of the two: it is never more than twice too small, and in practice it is usually right. For the exact value on a big network, the searches can be pruned with bounds, which is a different algorithm.

If the network is in pieces, every eccentricity is infinite and the diameter is nil. Measure each component on its own instead.

import AdjacencyListModule
import Distances
import GraphProtocols
import ShortestPaths
import Walks

let lanes = [
    UndirectedEdge("Ash", "Birch"), UndirectedEdge("Birch", "Cedar"), UndirectedEdge("Cedar", "Dale"),
    UndirectedEdge("Dale", "Elm"), UndirectedEdge("Elm", "Fir"), UndirectedEdge("Birch", "Glen"),
    UndirectedEdge("Glen", "Dale"), UndirectedEdge("Glen", "Holt"), UndirectedEdge("Holt", "Elm"),
    UndirectedEdge("Holt", "Ivy"), UndirectedEdge("Ivy", "Fir"), UndirectedEdge("Cedar", "Glen"),
]

let drivingMinutes: [UndirectedEdge<String>: Int] = [
    UndirectedEdge("Ash", "Birch"): 12, UndirectedEdge("Birch", "Cedar"): 7, UndirectedEdge("Cedar", "Dale"): 9,
    UndirectedEdge("Dale", "Elm"): 6, UndirectedEdge("Elm", "Fir"): 14, UndirectedEdge("Birch", "Glen"): 5,
    UndirectedEdge("Glen", "Dale"): 11, UndirectedEdge("Glen", "Holt"): 8, UndirectedEdge("Holt", "Elm"): 4,
    UndirectedEdge("Holt", "Ivy"): 6, UndirectedEdge("Ivy", "Fir"): 5, UndirectedEdge("Cedar", "Glen"): 3,
]

let county = UndirectedAdjacencyList<String> {
    for lane in lanes { lane }
}

let hops = county.eccentricities()
let radius = hops.radius  // 3
let diameter = hops.diameter  // 5
let center = hops.center  // ["Cedar", "Dale", "Glen", "Holt"]
let periphery = hops.periphery  // ["Ash", "Fir"]
