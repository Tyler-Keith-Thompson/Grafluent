Edge coloring

Say itvee-ZING/viˈzinɡ/

Every team plays every other once, and nobody plays twice on the same day. How few days does the tournament need?

Example: a small league where each team plays each other team once. A line is a match; a round is a set of matches with no team in two of them.

In SwiftThe league above, in Grafluent

import AdjacencyListModule
import ColoringModule
import GraphProtocols

let leagueTeams = ["Lions", "Tigers", "Bears", "Wolves", "Hawks", "Owls", "Foxes", "Sharks"]
let n = 6

let teams = leagueTeams.prefix(n)
let league = UndirectedAdjacencyList<String> {
    for (i, home) in teams.enumerated() {
        for away in teams.dropFirst(i + 1) { UndirectedEdge(home, away) }
    }
}

let rounds = league.edgeColoring()
let roundCount = rounds.colorCount  // 6
let firstRound = rounds.colorClasses[0].map { league.edges[$0] }  // [UndirectedEdge("Lions", "Tigers"), UndirectedEdge("Wolves", "Owls")]

// Seat the teams round a table, one seat fixed (an empty seat when the count is odd: a bye),
// and turn the others one place each round. Facing seats play.
let seats = n.isMultiple(of: 2) ? n : n + 1
var round: [UndirectedEdge<String>: Int] = [:]
for r in 0 ..< seats - 1 {
    let ring = [seats - 1] + (0 ..< seats - 1).map { (r + $0) % (seats - 1) }
    for k in 0 ..< seats / 2 where ring[k] < n && ring[seats - 1 - k] < n {
        round[UndirectedEdge(teams[ring[k]], teams[ring[seats - 1 - k]])] = r
    }
}
let proper = league.isEdgeColoring { round[league.edges[$0]]! }  // true

The ideaColour the edges so no two at a vertex match

An edge colouring gives every edge a colour so that the edges at any one vertex all differ. Each colour is then a set of edges with no vertex in common, a matching, and here each matching is a round of games that can be played side by side. The fewest colours is the graph’s chromatic index.

A vertex with Δ edges needs Δ different colours round it, so Δ is a lower bound. Vizing proved in 1964 that Δ + 1 is always enough for a simple graph. So there are only two possible answers, and edgeColoring() always reaches one of them: it runs Misra and Gries’s version of Vizing’s proof, colouring edges one by one and, when an edge is stuck, rotating a fan of colours round one end and swapping two colours along a path to free one up.

For the league, Δ is the number of other teams, n − 1. With an even number of teams, n − 1 rounds is possible: the circle method seats the teams round a table, keeps one seat fixed, turns the rest one place each round, and has facing seats play. With an odd number, each round leaves a team out, so n rounds are needed, and the circle method adds an empty seat for the bye. isEdgeColoring(_:) checks any colouring you bring.

Where it breaksΔ or Δ + 1 is a hard question

Vizing’s method promises Δ + 1 and sometimes gives it when Δ would do: switch to an even number of teams and compare its schedule with the circle method’s. That isn’t carelessness. Deciding whether a graph needs Δ or Δ + 1 colours is NP-complete in general, so no fast method always finds the smaller. On a bipartite graph, such as home teams against visiting teams, Kőnig’s theorem says Δ is always enough, and bipartiteEdgeColoring() finds it. For graphs with parallel edges, greedyEdgeColoring() works on anything, with at most 2Δ − 1 colours.

Real fixtures have more rules than this: home and away games, travel, rest days. Those are usually solved with constraint or integer programming, starting from a colouring like this one.
