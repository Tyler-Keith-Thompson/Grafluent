Communities

Say itloo-VAN/luvɛ̃/

Where does a network naturally split into groups?

What it’s forFinding groups nobody told you about

Community detection splits a network into groups that have many links inside and few between. You don’t say how many groups to find. The method works it out from the links alone.

The usual score is modularity. It rewards a split for links inside groups, beyond what chance would put there. Louvain is the standard way to find a split with high modularity. It is fast enough for networks with millions of links. Reach for it to find circles of friends, teams that work together, or topics in a web of pages.

Louvain is the usual first choice. Use Leiden when every group must hold together, and label propagation when speed matters most.

The ideaMore friendships inside groups than chance would give

A good split puts most friendships inside groups and few between them. But “most” needs a yardstick. Put everyone in one group, and every friendship is inside it. Modularity compares each group with chance. It takes the share of friendships inside the group. Then it subtracts the share you would expect if each person kept their number of friends but chose them at random. A split no better than chance scores 0. The clearer the groups, the higher the score.

The Louvain method raises modularity greedily. Everyone starts alone. Take each student in turn. Move them to the neighbouring group that raises modularity most, if any does. Keep sweeping until a full pass moves nobody.

Then merge each group into a single dot. The friendships between groups become weighted links. Do the same again with whole groups. It stops when merging no longer helps. Each sweep takes time in step with the number of friendships.

Where it breaksModularity has a blind spot

In a big network, modularity can’t see groups below a certain size. So two small, tight groups may come out merged. Raising the resolution parameter favours smaller groups.

Louvain can also leave a group that isn’t connected inside, after its middle member moves away. The Leiden method, leidenCommunities, adds a step that rules that out. And the greedy moves depend on the order students are visited. So the answer is a good split, but not always the best one.

Sometimes you want groups where everyone knows everyone. That is a different question, answered by cliques.

import AdjacencyListModule
import CommunityDetection
import GraphProtocols

let friendships = [
    UndirectedEdge("Ada", "Bo"), UndirectedEdge("Ada", "Cal"), UndirectedEdge("Ada", "Dot"),
    UndirectedEdge("Bo", "Cal"), UndirectedEdge("Bo", "Dot"), UndirectedEdge("Cal", "Dot"),
    UndirectedEdge("Eve", "Finn"), UndirectedEdge("Eve", "Gia"), UndirectedEdge("Finn", "Gia"),
    UndirectedEdge("Finn", "Hugo"), UndirectedEdge("Gia", "Hugo"),
    UndirectedEdge("Ivy", "Jay"), UndirectedEdge("Ivy", "Kim"), UndirectedEdge("Jay", "Kim"),
    UndirectedEdge("Jay", "Leo"), UndirectedEdge("Kim", "Leo"), UndirectedEdge("Ivy", "Leo"),
    UndirectedEdge("Dot", "Eve"), UndirectedEdge("Hugo", "Ivy"), UndirectedEdge("Cal", "Kim"),
]

let school = UndirectedAdjacencyList<String> {
    for pair in friendships { pair }
}

let events = Array(school.lazy.louvain())  // 11 events
let clubs = school.louvainCommunities()  // [Ada, Bo, Cal, Dot], [Eve, Finn, Gia, Hugo], [Ivy, Jay, Kim, Leo]
let score = school.modularity(of: clubs)  // 0.515
