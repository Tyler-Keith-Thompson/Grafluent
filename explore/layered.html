Layered drawing

Say itsoo-gee-YAH-mah/sɯɡijama/

How do you draw a flowchart so that every arrow points down and few of them cross?

What it’s forDrawings where direction matters

A layered drawing puts every vertex on a row, so that the arrows point down. Whatever comes first is drawn higher, and you can read the order from the top. It also moves vertices along their rows to keep arrows from crossing.

Reach for it for flowcharts, build pipelines, family trees, call graphs and anything else where arrows mean “comes before”. For a plain tree, such as an org chart, a tidy tree drawing does the same job more simply.

A layered drawing makes order easy to read, at the cost of more work. When the graph is a tree, the tidy tree is faster and never crosses. In the table, n is the number of vertices and m the number of edges.

Example: the steps of a software build, each arrow from a step to one that waits for it. A layered drawing puts each step on a row, below everything it waits for.

Each level of the chart is a row, and each manager sits centred over their team. Teams pack as close as they can without overlapping. Two teams of the same shape are drawn the same way.

The ideaOne hard problem, split into easier ones

Drawing a directed graph well is hard all at once. So Sugiyama, Tagawa and Toda split it into phases, each solved on its own. First, break the loops by turning a few arrows around. Second, give every vertex a layer so the arrows point down, and keep them short. Third, cut long arrows into pieces at every layer they cross. Fourth, order each layer to avoid crossings. Last, choose exact positions along each layer.

Grafluent’s sugiyamaLayout() uses a minimum feedback arc heuristic for the first phase and Gansner’s network simplex for the layers. It orders the layers by barycentre sweeps and places them by Brandes and Köpf’s method.

Trees need much less. A tree already has layers, its depths, and nothing to cross. Reingold and Tilford draw each subtree on its own. Then they push neighbouring subtrees together until their outlines touch at the minimum spacing, and centre each parent over its children. reingoldTilfordLayout() does this in linear time. It draws two subtrees of the same shape the same way, which is what makes a tidy tree look tidy.

Where it breaksCrossings, and wide layers

Finding the order with the fewest crossings is NP-hard even for two layers. So the sweeps are a heuristic. They usually do well, and the drawing reports its crossingCount so you can tell. A graph with many arrows between distant layers fills the drawing with bend points, and wide layers make a short, broad picture.

Loops have no right answer. Which arrows to turn around is a choice, and the smallest such set is itself NP-hard to find. The drawing lists them in reversedEdges, so a reader isn’t misled into thinking every arrow points down.

In SwiftThe pipeline and its phases, in Grafluent

import AdjacencyListModule
import GraphDrawing
import GraphProtocols
import Trees

let pipelineSteps = [
    DirectedEdge(from: "fetch", to: "compile"), DirectedEdge(from: "fetch", to: "lint"),
    DirectedEdge(from: "config", to: "compile"), DirectedEdge(from: "compile", to: "test"),
    DirectedEdge(from: "lint", to: "test"), DirectedEdge(from: "compile", to: "docs"),
    DirectedEdge(from: "test", to: "package"), DirectedEdge(from: "docs", to: "package"),
    DirectedEdge(from: "config", to: "package"), DirectedEdge(from: "package", to: "release"),
    DirectedEdge(from: "lint", to: "release"),
]

let rerun = false

let pipeline = AdjacencyList<String> {
    for step in pipelineSteps { step }
    if rerun { DirectedEdge(from: "release", to: "fetch") }
}

let layered = pipeline.sugiyamaLayout()
let crossings = layered.crossingCount  // 0
let reversed = layered.reversedEdges.map { pipeline.edges[$0] }  // []
let layers = pipeline.vertices.map { "\($0): \(layered.layer(of: $0))" }  // ["fetch: 0", "compile: 1", "lint: 1", "config: 0", "test: 2", "docs: 2", "package: 3", "release: 4"]

let reportsTo = [

let team = RootedTree(UndirectedAdjacencyList<String> {
    for (person, boss) in reportsTo { UndirectedEdge(boss, person) }
