Dominators

Say itLENG-ow-er/ˈlɛŋaʊ̯ɐ/

Which parts of a program are sure to have run by the time it reaches a given line?

What it’s forWhat every path must pass through

A block dominates another when every path from the entry to the second passes through the first. Dominators tell you what is sure to have happened before a point is reached. Post-dominators tell you what is sure to happen after it.

Compilers rely on them. They use dominators to find loops, to decide where values need merging, and to move code safely. The same idea finds the single points every route must pass in any network with one entry.

All three give the same tree. Lengauer–Tarjan has the best bound. The second lab on this page runs the slowest method, because it follows the definition.

Example: a function that adds up the numbers in a file, line by line. It warns about lines that aren’t numbers, and gives up after too many. Each block is a run of code with no jumps in it. The arrows are the jumps.

func total(of lines: [String]) throws -> Int {
    var sum = 0, bad = 0, count = 0            // entry
    for line in lines {                        // loop
        if let n = Int(line) {                 // check
            sum += n                           // add
        } else {
            bad += 1                           // warn
            if bad > 3 { throw TooManyBad() }  // give up
        }
        count += 1                             // next
    }
    return sum                                 // done
}                                              // exit

Dominators of exit

Every path from the entry to exit runs through entry and loop. The nearest, loop, is its immediate dominator and its parent in the tree. The exit can be reached through done or through give up, so neither one is unavoidable.

Dominator tree, from the entry

A block’s ancestors are what must run before it.

import AdjacencyListModule
import Connectivity
import GraphProtocols
import Traversal

// Each block of the function, and where it can jump next.
let jumps = [
    DirectedEdge(from: "entry", to: "loop"),
    DirectedEdge(from: "loop", to: "check"),    // another line to read
    DirectedEdge(from: "loop", to: "done"),     // no more lines
    DirectedEdge(from: "check", to: "add"),     // the line is a number
    DirectedEdge(from: "check", to: "warn"),    // it isn’t
    DirectedEdge(from: "add", to: "next"),
    DirectedEdge(from: "warn", to: "next"),
    DirectedEdge(from: "warn", to: "give up"),  // too many bad lines
    DirectedEdge(from: "next", to: "loop"),
    DirectedEdge(from: "done", to: "exit"),
    DirectedEdge(from: "give up", to: "exit"),
]

let program = AdjacencyList<String> {
    for jump in jumps { jump }
}

let tree = program.dominatorTree(root: "entry")

let block = "exit"

let chain = tree.dominators(of: block)  // ["exit", "loop", "entry"]
let parent = tree.immediateDominator(of: block)  // "loop"
let below = Array(tree.children(of: block))  // []

import Connectivity
import GraphProtocols
import Traversal

// Each block of the function, and where it can jump next.
let jumps = [
    DirectedEdge(from: "entry", to: "loop"),
    DirectedEdge(from: "loop", to: "check"),    // another line to read
    DirectedEdge(from: "loop", to: "done"),     // no more lines
    DirectedEdge(from: "check", to: "add"),     // the line is a number
    DirectedEdge(from: "check", to: "warn"),    // it isn’t
    DirectedEdge(from: "add", to: "next"),
    DirectedEdge(from: "warn", to: "next"),
    DirectedEdge(from: "warn", to: "give up"),  // too many bad lines
    DirectedEdge(from: "next", to: "loop"),
    DirectedEdge(from: "done", to: "exit"),
    DirectedEdge(from: "give up", to: "exit"),
]

let program = AdjacencyList<String> {
    for jump in jumps { jump }
}

let block = "loop"

var closed = program
closed.remove(block)
var reached: [String] = []
for case .discover(let v) in closed.lazy.breadthFirstSearch(from: "entry") {
    reached.append(v)
}
let cutOff = program.vertices.filter { !reached.contains($0) }  // ["loop", "check", "done", "add", "warn", "next", "give up", "exit"]

The ideaThe blocks you can’t get around

Each block has a chain of dominators running back to the entry. The nearest one is its immediate dominator. Every block except the entry has exactly one. So drawing each block under its immediate dominator gives a tree, the dominator tree. A block’s ancestors in that tree are exactly the blocks that dominate it. That is why dominates(_:_:) answers in constant time once the tree is built.

The second lab follows the definition. Take a block out and search from the entry. Whatever is cut off is what that block dominates. That costs one search per block.

Lengauer and Tarjan get every immediate dominator from a single depth-first search. First each block gets a semidominator. That is the earliest block, in the search’s order, with a path to it that detours only through later blocks. One more pass over the search tree turns semidominators into immediate dominators. Grafluent’s dominatorTree(root:) runs this algorithm.

Turn every arrow around and start from the exit instead. Then you get post-dominators, the blocks sure to run after a given one. postDominatorTree(exit:) finds them. A loop’s head dominates its body, which is how compilers find loops. The dominance frontier is where one block’s dominance stops. A variable assigned in two branches needs a merge there. dominanceFrontiers(root:) lists these frontiers.

Where it breaksCode nothing reaches, and code that never ends

A block the entry can’t reach has no dominators at all. “Every path passes through” means nothing when there is no path. So dominators(of:) returns nil for such a block, and not an empty list. That way dead code can’t be mistaken for code with no requirements.

Post-dominators have the same gap from the other end. A block that loops forever never reaches the exit. In a function with two exits, some paths never reach the exit you named. Give every exit a jump to one shared exit block first.

Dominance is about the jumps as drawn. It ignores the values that choose between them. Here give up only ever follows several warnings. But the graph sees one arrow from warn, and no count. What dominators promise holds on every path through the graph, so a compiler can rely on them. Facts that depend on the data are beyond them.
